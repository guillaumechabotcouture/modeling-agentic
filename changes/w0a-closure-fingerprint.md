## Changelog

**Reuse key narrowed to what a row depends on: the observed closure.** A stored batch row's reuse key (`scripts/compute.py`) no longer hashes every file under `scripts/` and `toolkit/`. `code_fingerprint` (`k3-`) hashes recorded parts: the run's `models/` and `data/` and the function's file (`run_files`), the dependency manifests (`deps`), the declared repo data read by path (`data_set`: `FP_DATA_SET`, the one list: `.claude/orchestration/` and `data/` whole, the non-Python files of `scripts/` and `toolkit/`, engine cards included), and `extra`, the engine identity `toolkit/analysis/batch.py` passes (`contract.engine_identity`). The repo code is the observed closure: after each job returns, the worker records the repo files its process has used, with their sha256: its `sys.modules` entries' `__file__` and the files it opened for reading (an audit hook installed before the model loads; run files only when Python), hashed first when the model has loaded (`_observe`; rows carry `observed_id` and, when the set changes, `observed`). Each summary and partial journal records the union in `key_parts.observed` with the set ids. A stored row is reused only when the key matches, its set is one the record holds, and every recorded file re-hashes the same here (`record_check`). Fail closed: a record with no observed closure (every batch stored before this change) is recomputed, recorded as `no_observed_closure` in the summary's `reuse_refused`; a missing or unreadable file, or one file with two contents, gives no reuse; a job whose process started a child process (`observed_child`, from the audit hook or the process's child accounting) is also keyed on the whole of `scripts/` and `toolkit/` (`tree`). `compute.py reuse-check` and the run console name the part or file that differs. The static import walk of the earlier W0-A commits is removed.
