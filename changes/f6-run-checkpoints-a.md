## Changelog

**Run checkpoints on the agent VM, fetch and resume from them, and a final checkpoint before the watch stops a launch (F6).** On 2026-11-11 the F6 preview ran 3 h and was stopped at its spend cap by `cloud/launch_watch.py`. A v2 run stores its run directory only when `main.py` ends, so nothing was stored and 3 h of engine batches were lost. (1) While `main.py` runs, `cloud/worker_side.py` `Checkpointer` uploads a tarball of the run dir every `checkpoint_minutes` (new `RunConfig` field, default 15, 0 off) to `outputs/<storage_prefix>/launch_<id>/checkpoint_<label>.tar.gz`, then its record `checkpoint_<label>.json` (time, size, sha256, run state and round, cached engine batches and rows). The tarball (`runs/<RUN>/...` and `run.log`) is built by the new `scripts/results_store.py` `write_archive` with the final store's exclusions (no `_truth/`, no credential files, API keys redacted); `upload_file` streams it and verifies the read-back. One upload runs at a time, a checkpoint due while one uploads is skipped, and a failure is logged and never stops the run. (2) `run_cluster.py <cfg> checkpoint [--label L]` downloads the latest checkpoint and refuses on a sha256 mismatch; `collect` says when a label has only a checkpoint; `checkpoint-now` asks the running thread for one checkpoint, bounded. (3) Resume steps are in the `run_cluster.py` module doc ("Checkpoints"); a run dir restored from a checkpoint reuses its finished engine batches and its interrupted batch's journal (`scripts/compute.py` reuse path). Known limit: a file over 64 MB under `models/` or `data/` is fingerprinted by size and mtime, which tar does not keep, so it makes every batch recompute (`reuse-check` shows it). (4) `launch_watch.py` runs `checkpoint-now` once, bounded, before the stops at its spend cap and at `--max-hours`; a failure never delays the stop, and the exit message names the checkpoint. Self-tests written first: CK1-CK12b (`run_cluster.py`), LW19a-LW19d (`launch_watch.py`), CP0-CP3 (`compute.py`), S8-S9 (`results_store.py`). Codex round 1 (each fix test-first): (P1-1) `scripts/compute.py` run_map's summary records `out_sha256`, the sha256 of the results file it describes, and `_reusable` reuses a finished batch's rows only when the results file matches it (a summary from before this field must at least count its rows), so a snapshot taken between the two writes recomputes that batch, logged; the checkpoint record's state and counts are read from the archive, not the live run dir. (P1-2) `results_store.write_archive` opens each file once, following no link at any component, regular files only, copies it to a temporary file and scans and archives that copy, so a rewrite or a swap for a link to `_truth/` after the listing can neither leak a secret nor reach the answer keys. (P1-3) `checkpoint_now_side` only files a request and returns its token at once (nothing waits on the worker's event loop); `checkpoint-now` then polls storage for a generation carrying the token or started after it. (P2-4) Each checkpoint is an immutable generation `checkpoint_<label>_g<N>.tar.gz` with its record `_g<N>.json`, then the pointer `checkpoint_<label>.json` names it; the last two complete generations are kept, and `checkpoint` falls back to the previous one when the latest does not verify. (P2-5) A checkpoint needs free space of 1.5 × the run dir + 2 GB, else it is skipped (logged); partial and local archives are removed on failure and after upload. (P2-6) `checkpoint-now` connects to the run cluster id `clusters.json` records (never by name) and refuses a record of another invocation or launch, or assignments of another launch; `launch_watch.py` passes its own invocation and launch id. (P2-7) A request made while an upload is busy stays pending and is met only by a checkpoint that started after it. (P2-8) Every label is requested first, then all are awaited under one deadline. Tests: CK13-CK20 (`run_cluster.py`), S10-S13 (`results_store.py`), CP4-CP6 (`compute.py`; CP4 is the hop through the launch tree: committed with `add -f`, archived, extracted, rows reused), LW24 (`launch_watch.py`). The large-file limit above stands. The dollar cap measured from Coiled's bill, the checkpoint requirement and the signed-budget check follow in a separate PR.
