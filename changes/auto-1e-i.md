## Changelog

**Storage durability: streaming store and fetch, timeouts, retries, checkpoint health.** `scripts/results_store.py` keeps one blob client per account for the life of the process, built with connection and read timeouts (30 s, 120 s), and passes a 300 s timeout on every call. `upload`, `upload_retry` (also named `upload_file`) and `download` (also `download_file`) stream: the file goes up as a stream, the read-back and the download are hashed chunk by chunk, and a download is written under a temporary name and renamed only when complete (new `lib.safe_io.stream_nofollow`), so a failed fetch keeps the earlier copy. Uploads and downloads retry five times with waits of 4, 8, 16 and 32 s; a blob that does not exist raises at once. A client that takes neither a stream length nor a timeout (a whole-bytes test double) is called the plain way. `write_archive` redacts a file over 64 MB block by block instead of leaving it out when it holds a secret. `agents/run_finish.py` `store_run_results` writes the run archive to a temporary directory with `write_archive` and streams it up; it no longer builds the archive in memory. `cloud/worker_side.py`: `run_job_impl` writes `result.tar.gz` to disk instead of returning its bytes, and leaves files over 50 MiB out only when main.py ended by itself and its own verified store has them (a killed run's receipt is not trusted), and falls back to a tarball without them when the complete one cannot be written; the transcripts go through the streaming writer (`store_transcripts`); `store_outputs` and `run_cluster._download` hash block by block; `run_to_disk` removes its unpacked code when the task ends and, at teardown, waits up to 90 s for a checkpoint upload in flight (`stop_checkpointer`); the checkpointer writes its counters, last stored generation and last error to `.checkpoint/status.json` after every attempt. Self-tests: `results_store.py` S18–S24, `run_cluster.py` WS1–WS6, `safe_io.py` S12e–h. Not in this change: liveness, watchdog and budget bookkeeping (1E-ii); `agents/observability.py` live snapshots still use the in-memory `archive_dir`; `vm_job` `sync_outputs` still downloads a changed file from byte 0 (2D).
