## Changelog

**Run console: the stream opens on a summary and reads in half the height.** The owner asked for a UI/UX review of the console for following a run's progress. The review was done on screenshots of three kept runs (headless Chrome, 1440×900 and phone width); fifteen findings, all in the page (`run_console.html`, `run_console.js`, one line of `dossier.js`), no server change. **Order:** the stream opens at the top on a new card, "Where this run stands": whether anything needs the owner (first row, with a jump to the decision card), the result so far, the last gate action with its done-when counts, the critique round (blockers, open HIGH, resolved), how many decision tests change the plan, figures and documents, each with a jump. It used to open scrolled to the newest card. **Grouping:** stage transitions that follow one another read as one line (Spec → Sign → Evidence …, each step with its note, spend and time behind "more"); the analysis figures are one card with a grid; a gate's done-when tests are folded under their counts, one row per blocker, and the judged text is no longer repeated in the detail column. On the F4 run the stream is 3,123 px high (about 6,900 before) and the fixed header, stepper and composer take 261 px (351 before). **Header:** the run's label is the title, the project is above it, the question is behind a "Question" button, and a stopped run says where and why it stopped. **Refresh:** the page asks for the run every 20 s; an unchanged answer no longer redraws the stream, and a changed one keeps the rows and tables the reader had opened and the scroll position (toggle ids are now stable keys, not counters). **Composer:** with chat off (no API key), Record is the one action and the hint says notes are recorded as feedback; the kind and anchor options show on focus. **Other:** "Needs you: no" is quiet and "Needs you: yes" is marked; the sidebar shows engine and end state only for related runs and drafts, and drafts carry their full label; the decision-test and parameter-registry tables have fixed column widths so long ids wrap inside their cell; the side panel hides the run list below 1,700 px instead of squeezing the stream; the Learning tab says when it has no entries; the address carries the run and the view (`#run=…&view=…`), so a reload or a shared local link returns to the same place. Self-tests RU1-RU5 (`run_console.py`; RU1-RU3 run the page script in node) fail on the previous page and pass now; they were written after the page change was drafted against the screenshots. Left as is: stage cards with equal timestamps are ordered by the page, not the server.
