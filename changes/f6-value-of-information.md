## Changelog

**Value of information from the uncertainty draws (owner, 2026-11-12).** The analysis step now says which uncertain input is worth better data, from the draws it already evaluates (no new engine runs; ILP solves on those tables only). A read-only `on_solve` hook in `UQ.run` hands each draw's sampled inputs, benefit and cost tables, re-optimised plan and model corrections to `toolkit/analysis/value_of_information.py`, which writes `analysis/value_of_information.yaml` (new artifact kind). Deciding now is the best plan within the allocatable budget in every draw (one solve with a budget row per draw beside the signed caps; with an overspend allowance, the best candidate within it, labelled a lower bound). Perfect information takes, in each draw, the best plan feasible there, overspending in no more draws than the plan chosen now may, so EVPI is never inflated by overspending. Candidates (the headline plan, plan variants, the plan decided now, each draw's optimum and the plan decided within each quantile bin of each input and group) that break the signed feasibility or carry a model correction in any draw are reported with their regret, never chosen. EVPPI per drawn input and group by the regression method of Strong, Oakley & Brennan 2014 (natural cubic spline, knots by GCV), with feasibility after learning judged within the input's bins, over the candidate set; each value carries a permutation noise floor computed with the full procedure (GCV repeated), no percentile interval, and is claimed only when supported (above its floor, not above EVPI). Below 30 draws the artifact records too_few_draws; below 500 values are indicative (thresholds.yaml `value_of_information`, proposals for the owner). Inputs not drawn are listed with why. Claims, a results.md section and a contract check (`analysis_contract_value_of_information`: the EVPI identity, signs, diagnostics, the chosen candidate, status consistency; fail closed); `enabled: false` turns it off with the uncertainty outputs unchanged. Review round 2: plans decided within an input's bins are built on one half of the draws and valued on the other (cross-fitting), so an irrelevant input is no longer supported in nearly every replicate; perfect information may overspend with each draw's plan solved without the budget; the policy chosen after learning keeps the affordability share; a discrete input is binned by value; the gate recomputes eligibility and reconciles the value of deciding now with the candidate table. Review round 3: a group too large for the draws is recorded as not computed instead of stopping the analysis; perfect information decides identically in identical draws; a corrected per-draw solve is replaced by the best clean plan; the gate takes the affordability allowance from the signed spec and recomputes eligibility before accepting no_eligible_plan; results.md shows the supported rows the claims cite. Self-tests VI1-13, VG1-7, VR1-7 and the reviews' reproductions D1-D10 (round 1), E1-E5 (round 2) and F1-F6 (round 3), written first, failed before each change.
