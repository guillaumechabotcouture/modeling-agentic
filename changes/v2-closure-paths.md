## Changelog

**A run dir given as a relative or an absolute path keys the signed input closure the same way.** Found on the F6 dry-run stand-in. `evidence_dossier.input_closure`, which writes the closure that the sign-off sheet records and that `signoff.preconditions_state` checks, resolved the spec's inputs against the spec's base. With a relative run dir (`runs/<R>`) that gave paths relative to the working directory, which were then joined to the run dir again. The closure keyed the same files as `run:runs/<R>/data/...` instead of `run:data/...`, so a spec signed through one path form had the status `changed` through the other (launchers, `main.py --resume`). `input_closure` now makes the run dir absolute before resolving, so every key is relative to the run dir in either form. It is one producer for the sheet, signing and status, so the fix covers all of them. Signatures made through an absolute run dir keep their keys exactly, so they verify as before. A package signed through a relative run dir holds the doubled keys; it reports `changed` in either form and must be re-signed, after the sheet is regenerated. SG-RD1 and SG-RD2 in `signoff.py` (sign relative and check absolute, and the reverse; run keys relative to the run dir) were written first and failed before the change (α-β). Codex's read-only review found no P1 in this change. Its P2 is fixed: SG-RD2 now requires `run:units.csv` with the fixture file's own sha256 (γ). It raised four P1s that predate this change and are left for a follow-up: (1) a symlink alias of the run dir (`/tmp` and `/private/tmp`) with an input named by its physical absolute path keys it differently; (2) a symlinked input inside the run dir is hashed as `absent`, so an edit of its target is not seen; (3) a run without a dossier does not compare its closure with the sheet's; (4) a `unit_attribute.set_from` CSV is not in the closure.
