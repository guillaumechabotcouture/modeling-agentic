## Changelog

**v2 autonomy 1B-ii (b): the EVIDENCE stage drafts the evidence dossier before SIGN (owner default D1).** A spec whose options need decision inputs could not be signed without an evidence dossier, and no run task could write one, so a run under `--signoff lead` waited at SIGN indefinitely (the measles and flu eval specs) and one under `--signoff none` failed at ENGINE_CHOICE. The order is now SPEC, EVIDENCE, SIGN, ENGINE_CHOICE. `h_EVIDENCE` uses the helpers of 1B-ii (a) (`toolkit/spec/evidence_draft.py`): with no decision input it passes with no task (`evidence/dossier_draft.json` status `not_required`); a spec that needs inputs and names no dossier goes back to the draft with the reason; otherwise the harness scaffolds the missing entries and the bounded `draft_evidence` task (owns `evidence_dossier.yaml` only, never another file a spec names) fills the evidence, at most three drafts in a run (counted from the journal), each time with the check's problems. The stage then records `evidence/dossier_draft.json` and rewrites the sign-off sheet, which binds the dossier (the sheet's candidate rows are recomputed first in a resumed process). A refused lead sign-off goes back to EVIDENCE (a dossier refusal) or SPEC (anything else, one more draft) at most twice (`MAX_SIGN_REPAIRS`), then waits for the owner; the check itself is unchanged. A spec that was ever signed (a record, current or stale, or a signature in the run's history) is never re-signed by the lead, and at EVIDENCE goes to SIGN, which checks the signer and the approvals; an unsigned run saved at SIGN under the earlier order runs EVIDENCE first. The lead's sign-off note and the report (`## Evidence dossier`, rendered by the harness from the record that binds the spec) state who drafted and who signed the dossier, mark it provisional unless the owner signed, and list every gap. The deliverable may not be the dossier or the sheet. The launch check (`cloud/run_cluster.py` `stale_sheet_problems`) treats a run at EVIDENCE as a draft unless a sign-off record or a signature in its history exists (RC80f); the run console counts a run at EVIDENCE as not past sign-off. The draft-spec prompt and the decision-spec skill tell the spec task to name the dossier and not write it. γ: narrow Codex review, round 1. Not in this PR: finding a dossier the spec does not name (audit 1B 1.i: it would change what a signed spec means), pausing a lead run on an evidence-versus-engine difference instead of declaring it (D2), and narrowing the input closure (1.l).
