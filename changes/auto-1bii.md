## Changelog

**v2 autonomy 1B-ii: the EVIDENCE stage drafts the evidence dossier before SIGN (owner default D1).** A spec whose options need decision inputs could not be signed without an evidence dossier, and no run task could write one, so a run under `--signoff lead` waited at SIGN indefinitely (the measles and flu eval specs) and one under `--signoff none` failed at ENGINE_CHOICE. The order is now SPEC, EVIDENCE, SIGN, ENGINE_CHOICE. `h_EVIDENCE` asks `toolkit/spec/evidence_draft.py` what the options need (the signer's own `evidence_dossier.required_inputs` and `check`): with no decision input it passes with no task (`evidence/dossier_draft.json` status `not_required`); a spec that needs inputs and names no dossier goes back to the draft with the reason. Otherwise the harness scaffolds each missing entry with what execution uses (model value and source, and the engine's value as `chosen`, with the generated range test for a drawn parameter), computed by the dossier module's execution view, and never writes observations or `no_data`; the bounded `draft_evidence` task (owns `evidence_dossier.yaml` only, never another file a spec names) fills the evidence, at most three times in a run, each time with the check's problems. The stage then writes `evidence/dossier_draft.json` (inputs, tries, problems left, the dossier's sha256 and the declared gaps: inputs with no data, a chosen value that differs from what execution uses, a value left at the engine's, a source the harness could not locate as a file) and rewrites the sign-off sheet, which binds the dossier. A refused lead sign-off goes back to EVIDENCE (a dossier refusal) or SPEC (anything else, one more draft) at most twice (`MAX_SIGN_REPAIRS`), then waits for the owner; the check itself is unchanged. The lead's sign-off note and the report (`## Evidence dossier`, rendered by the harness) state who drafted and who signed the dossier, mark it provisional unless the owner signed, and list every gap. A run signed under the earlier order and resumed at EVIDENCE goes on to ENGINE_CHOICE with its dossier untouched. The draft-spec prompt and the decision-spec skill tell the spec task to name the dossier and not write it. Not in this PR: finding a dossier the spec does not name (audit 1B 1.i: it would change what a signed spec means), pausing a lead run on an evidence-versus-engine difference instead of declaring it (D2), and narrowing the input closure (1.l).
