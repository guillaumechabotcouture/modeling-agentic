## Changelog

**Declared calibration misses, each tied to a decision test (owner decision R1, F6 run 1).** F6 run 1 stopped in joint calibration on the verification of `state_2018:Katsina` and on the Yobe shared offset's region-sample shortfall. The diagnosis (2018→2021 trend and campaign-only nets) is in the F6 amendment notes. `unmatched_decision` let only unit misses proceed. `calibration.joint.unmatched.declared` now lists known misses the run proceeds with, under mode flag. Each entry is `{target: <group target id>:<group>, reason, decision_test}`, for a group target the verification fails, or `{offset: <bias_source>|<group>, reason, decision_test}`, for a shared offset whose region-sample rows fail. `_declared_problems` refuses at spec time anything but exactly one selector, a reason, a decision test declared in `analysis.decision_tests`, and an identity the spec's targets generate (`<group target id>:<group>`, `<bias_source>|<group>`), matched exactly, so identifiers holding `:` or `|` work. At run time, a verification target failure proceeds only when it is declared. An `offset_sampling_low_acceptance` block proceeds only when its new breakdown (`history_matching._offset_draws` now records `failed_rows` and, per component, `by_component: [{blocks: [exact block keys], rows: [failed rows]}]`) covers every failed row and names only declared offsets, matched by exact key, never by splitting a string. Any other block still blocks, and a report without the breakdown fails closed. The decision records `declared` (with the target's verified implausibility or the component's failed rows). `toolkit/analysis/run.py` then blocks the analysis (`declared_miss_untested`) unless every declared miss's decision test ran (`declared_test_problems`). A report whose blocks contradict `blocked: false` is judged by its blocks. Self-tests JA27a-i and HM34c: α's JA27a, c, f and HM34c, and β's JA27c, g, h and HM34 (Codex's review of 957de1d: 1 P1, 3 P2) failed first.
