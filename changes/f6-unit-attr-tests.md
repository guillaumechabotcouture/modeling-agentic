## Changelog

**A decision test can vary a unit attribute: a units-table column that feeds an engine unit attribute.** New type `unit_attribute` (`toolkit/analysis/decision_tests.py`): `unit_attribute: {column, units: [ids] | all, values: [..] | scale: [..] | set_from: <table in the run directory>}`. Each case is a copy of the table `Spec.units()` read, in place for that case only (`units_table`: the spec's reader cache, the analysis rows, feasibility, the model's engine attributes and emulator features are rebuilt by the functions that built them, then restored). The calibration is redone on the emulator-inversion path and held at the headline values otherwise, and the record says which. One planner (`plan_unit_attribute`) is used both at sign-off (`schema.validate`) and at run time. It refuses an unknown column, a column bound to no engine attribute or only to the calibrated one, unit ids not in the table, a value mode other than exactly one of values, scale or set_from, a set_from table outside the run directory, a case outside the attribute's declared domain (`EngineCard.valid_ranges`; an attribute without one is refused), on the emulator path a column that reaches no emulator feature or leaves the design box, and a test whose every case is an identity. The record (`models/decision_tests/<id>.yaml` key `unit_attribute`) names the column, attributes, units changed per case and the sha256 of each modified table and of the base table. A set_from table is a hashed input of `analysis/decision_tests.yaml`. This closes the decision-test half of the unit-attribute uncertainty gap in `docs/design/v2-progressive-steps.md` §6.7. Drawing unit attributes in the uncertainty draws is still open. Self-tests SP-UA1-10 (`toolkit/spec/schema.py`) and UA1-16 (`toolkit/analysis/run.py`).
