## Changelog

**A refused calibration: chains started at the posterior mode, and a planned spec patch before the pause (hb3 triage fix 2).** Flu R1 refused its 11-parameter observation-target posterior identically in hb1 and hb3 (adaptive Metropolis, R-hat and bulk ESS far below the floors), while R2 calibrated the same model and data. The likely cause is that the chains started from prior draws and shared one proposal covariance. (a) New `toolkit/analysis/mode_start.py`: above `max_importance_params`, the observation-target fit (`observed_targets.fit`) samples with adaptive Metropolis started at the posterior mode. The best 8 of 2^6 Sobol scan points are each moved to a mode by L-BFGS-B, with batched central-difference gradients. A Laplace covariance comes from a finite-difference Hessian, with eigenvalues floored at the prior's precision. Modes whose Laplace mass is more than log 1000 below the best one are dropped. The chains start overdispersed (2x) around the kept modes. Each chain adapts its own proposal on its own history, shrunk towards its Laplace covariance. A refusal is retried once from new starts before it is final, and the final message names both attempts. The convergence floors are unchanged. Up to `max_importance_params`, and when no scan point is finite, `calibration.sample` is used as before. The mode search counts as a start search, so its engine refusals are reported as `start_search_refusals`. `toolkit/analysis/calibration.py` is byte-identical, so the compartmental coverage pack (calibrator `calibration.posterior`, which never reaches this path) and its proof (compat_proof.py CP8) need nothing. (b) `agents/stage_machine.py`: when a calibration is refused under a signed spec, the fix planner is first asked for one SPEC rethink with a patch on `calibration.*` paths only (its method, priors or parameter set). The planner gets one retry when the plan does not validate, and below the task floor it is skipped. The result is recorded in `calibration_patch_r<round>.json`. `rethink_request` reads it: under `--signoff lead` the request carries it as `patch`, so `_lead_amend_locked` makes the provisional child. Under owner sign-off it is `proposed_patch`, written to `spec_patch_proposed.json`, which `amend --from-request --patch` reads as written; a fix-loop plan's patch is now proposed to the owner the same way. With no valid patch, the run pauses as before. The redraft branch of #339 is kept for unsigned specs (`--signoff none`, the only mode in which SIGN does not sign), and its history line now says "redraft n of 2". Under a signed spec the line says the calibration needs an amendment. Self-tests MS1-MS5b (mode_start), CRF5-CRF8 (stage_machine).
