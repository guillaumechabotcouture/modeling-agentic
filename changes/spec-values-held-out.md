## Changelog

**A spec value chosen with a held-out benchmark cannot be signed (follow-up to #133).** An F5 spec set an engine parameter to the value that put two held-out benchmarks in band, and its reason said so. The sign-off sheet showed only a HIGH "outside card range" note, and the owner was asked to accept it. A value fitted to a held-out benchmark leaves that benchmark nothing to test, so it is now refused, not flagged. (1) Structured basis, the main check: every `engine_parameters` entry needs `basis: literature | setting_data | owner_judgement | fitted`. A missing, unknown or non-text basis is refused. With `fitted`, `fitted_to` is required: a non-empty list of distinct benchmark ids. It is refused with any other basis. Each id is resolved against the engine's own benchmark pack (`benchmark_pack()`: the class attribute `BENCHMARK_PACK`, else `benchmarks/pack.yaml` beside the engine's module; never the spec or the engine configuration; the pack must name the class). An id not in the pack is refused. An id the pack holds out (every benchmark not in `toolkit/engines/benchmark.py fit_targets`) is refused with "held-out benchmark". An engine without a pack cannot resolve `fitted_to`, so it is refused. (2) Text backstop, not the main check: a `source` or `reason` that names a held-out id of the engine's pack is refused the same way. It matches by word against the pack's own ids, case-insensitively, so `B7b` does not match `B7`. The toolkit names no disease and no id. (3) Where it bites: `schema.validate` (per engine, so each pre-sign candidate and the chosen engine), the sign-off sheet (a **REFUSED** block, and each value's basis), `toolkit/spec/signoff.py sign` (also with `engine: auto`, where the pending checks do not load an engine) and `scripts/decision_brief.py sign`, which signs the spec with the brief but did not validate it. Both signers call `signoff_refusals()` on the bytes they sign, whoever signs. No flag, note or `--by owner` overrides it. With no engine known yet (`engine: auto`, no candidates), a fitted value is refused and the backstop reads every engine pack in the repository. An engine that does not load refuses signing a spec that has the field. Tests, written first: `engine_parameters` EP43–EP53 (toy pack `toolkit/spec/toy_engines_pack.yaml` beside `ToySpecEngine`: fit targets TF1–TF2, held out TH1–TH2; the real packs are read only), `signoff` SV8–SV10 (the signoff CLI with `--by owner` included), `decision_brief` DB38–DB39 (in process for the owner and the lead, and the CLI with `--by owner`, on a real engine's pack with the id read from it). Existing self-test entries now carry a basis. Review round 1 (Codex), each with a regression test: a pack that exists but cannot be read, names another engine, or has the wrong shape (a benchmark that is not a mapping, a non-text or repeated id, fit targets that are not a list of the pack's ids) refuses every value whatever its basis, instead of being skipped or coerced (`PackError`; EP54), and so does an unreadable pack in the no-engine fallback (EP56); an engine declaration with both `auto: true` and `ref` is refused, and the sheet's engine list follows the schema (auto wins) so the candidates are checked (EP55); an engine that does not load refuses (EP57); EP53 checks the pack ids independently of `pack_ids`; the spike signer `agents/stage_machine.py sign` refuses too (IG-M7); DB38's in-process cases check the refusal's reason. Review round 2 (Codex): the signers resolve engines from the signed spec alone (its ref, else its listed candidates, else every engine pack), never from `engine_choice.json`, which can change after signing (EP58); a pack or engines directory that cannot be reached (an error other than not found) refuses instead of reading as absent (EP59); `auto` that is not true or false is refused, and a truthy `auto` counts as auto everywhere, as `agents/analysis_backend.py` reads it (EP60). Retro-check on the F5 spec (read only, not in the repository): `net_retention_half` is refused as it stands (no basis, and held-out ids in its source and reason). It is also refused with `basis: fitted` and those ids in `fitted_to`, and with `basis: owner_judgement`.
