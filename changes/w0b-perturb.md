## Changelog

**One generic decision test, `perturb` (Wave 0, W0-B).** A spec declares a decision test as `type: perturb` with a `set` of targets: what is moved (`parameter`, `unit_column`, `cost_item`, `calibration_target`, `outcome`, `burden`, `interaction`, `envelope`, `group_rule`, `boundary_engine`), how (set by `values`/`value`, `scale`, `shift` or a range end) and to what. The new module `toolkit/spec/perturb.py` holds the format. The ten older types and the harness's automatic ones are aliases: `compile` translates each to `perturb` without loss (`view(compile(dt)) == dt` for every shape). `decision_tests.run_one` runs every test through that translation and executes the per-target form with the existing branches. Each record keeps its own type (`perturb` for a native test) and gains a `perturb` field: the compiled test with the layer it acts on (`post_emulator`, `emulator_design` or `engine`) and its engine row count. Readers of declared tests read the per-target form through `perturb.tests`: validation, the design box, the sign-off checks, the evidence dossier, the pre-sign critique and the effect-by-setting check. So a native test gets the same checks as its alias. More than one target is allowed for parameters (the first swept, the others held) and for cost items (one price case). A joint parameter test is conditional, as #294 ruled: it carries no departure and is no dossier range test. Unknown targets, mixed kinds, harness-only targets and declared aliases are refused. A `unit_column` target can also `shift` a column. The golden records of the older types (`toolkit/analysis/dt_golden.json`) are unchanged. Tests written first: PT1–PT21, SPP1–SPP6, RPT0–RPT3. Not yet done: showing the layer and row count on the sign-off sheet.
