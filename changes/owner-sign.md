## Changelog

**Owner-signed sign-offs: the owner's Ed25519 key signs the spec and scope-declaration sign-offs, and the harness verifies them where it consumes them.** Owner decision 2026-11-23. The key handling of `cloud/budget.py` moves to `scripts/lib/owner_key.py`, which budget.py now imports: the same keychain item (`modeling-agentic-budget-owner`, no trusted application, so each read raises the keychain dialog) and the same tracked public key (`cloud/budget_owner.pub`). `sign_bytes` is the only place the private key is read, and it zeroes the buffer afterwards. `BudgetError` is now the shared `OwnerKeyError`. `agents/stage_machine.py sign --by owner` (through `toolkit/spec/signoff.py` and, with a brief, `scripts/decision_brief.py`) and `scripts/scope_signoff.py sign --by owner` sign a canonical payload before anything is frozen or written. The payload holds purpose, kind, run id (the run directory's name), artifacts (the spec, the sign-off sheet and every hash the record binds; or the scope request), decision (for scope: each fingerprint's finding and accept or decline, with the round) and signed_at. The signature goes into the sign-off record as `owner_signature`, or into each answer of the batch. The harness verifies it when leaving SIGN (`Machine._signed_by`), when leaving OWNER_DECISION (`scope_signoff.load_answers` drops an owner answer that does not verify, so every consumer waits for the owner), and on `--resume` past SIGN (run_failed, with how to sign). Verification fails closed: a missing public key, a bad or replayed signature, another run's signature, or a spec or record hash that differs from the signed one refuses, and the message names the sign command. Lead sign-offs are unchanged and unsigned, and never count as the owner's. An owner record that does not verify can be signed again by the owner. Legacy: an unsigned owner record made before `LEGACY_CUTOFF_UTC` (2026-11-25T00:00Z) counts, labelled `owner_signature: "unsigned (legacy)"` in the run history; after the cutoff it is refused. Test key: a `--self-test` process signs with a throwaway key exported as `MA_OWNER_TEST_KEY` to its children. It never touches the keychain. `main.py` refuses a run with that variable set, and `filtered_env` blanks it for agents. `enforcement.owner_command_reason` also denies agents the keychain item (`security ... -generic-password`, `security -i`), `budget.py init-key` and `owner_key`. Open item: `cloud/run_cluster.py <config> sign` signs on the worker, which has no keychain, so owner sign-offs of cloud runs are refused until a follow-up adds prepare-on-worker, sign-on-laptop. Self-tests OK1-OK11, OS1-OS5 (scope_signoff, stage_machine), OSG0-OSG3, OSK1-OSK2, and budget BK3c updated. Smoke markers: `decision_spec.signoff.json:owner_signature`, `run_state.json~"owner_signature": "signed"`, and `scope_signoff.json~owner_signature` when a scope item is answered.
