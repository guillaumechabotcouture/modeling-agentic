## Changelog

**Owner-signed sign-offs: the owner's Ed25519 key signs the spec and scope-declaration sign-offs, and the harness verifies them where it consumes them.** Owner decision 2026-11-23. The key handling of `cloud/budget.py` moves to `scripts/lib/owner_key.py`, which budget.py now imports: the same keychain item (`modeling-agentic-budget-owner`, no trusted application, so each read raises the keychain dialog) and the same tracked public key (`cloud/budget_owner.pub`). `sign_bytes` is the only place the private key is read, and it zeroes the buffer afterwards. `BudgetError` is now the shared `OwnerKeyError`. `agents/stage_machine.py sign --by owner` (through `toolkit/spec/signoff.py`, or `scripts/decision_brief.py` when there is a brief, whose own CLI signs too) and `scripts/scope_signoff.py sign --by owner` sign a canonical payload before the record is written. The payload holds purpose, kind, run id (the run directory's name), artifacts, decision and signed_at. For the spec, the artifacts are the spec's sha256, the sign-off sheet's and the digest of the whole record, so its answers and its evidence and review-condition bindings are signed. For scope declarations, the artifact is the request, and the decision is each fingerprint's finding and accept or decline, with the round. The signature is stored as `owner_signature`. The harness verifies it in four places. `toolkit/spec/signoff.py status` reports a refused owner record as `changed`. The machine leaves SIGN only on a verified record (`Machine._signed_by`). `scope_signoff.load_answers` drops an owner answer that does not verify, so OWNER_DECISION, the gate and the run console wait for the owner. On `--resume` past SIGN, an owner run needs a verifying owner record: a lead's record, no record or a bad one ends `run_failed`, with how to sign. Verification fails closed: a missing public key, a bad signature, another run's signature, or a hash that differs from the signed one refuses, and the message names the sign command. Lead sign-offs are unchanged and unsigned, and never count as the owner's. The owner may sign again over a refused record only while the spec is still the bytes it records. A refused scope answer stays in the record. Legacy: an unsigned owner record counts only while it is verified before `LEGACY_CUTOFF_UTC` (2026-11-25T00:00Z) by the verifier's clock, never by the record's own forgeable time. It is labelled `owner_signature: "unsigned (legacy)"` in the run history. From the cutoff on, every unsigned owner record is refused with the sign command. Test key: only an explicit in-process opt-in turns it on (`owner_key.enable_test_key`, called by a process started with `--self-test`, or `keyed_argv` for a self-test's child). No environment variable is consulted, so a production sign or verification always uses the keychain and the tracked public key (OK12 shows it for scope_signoff, run_console, stage_machine, decision_brief and budget). `enforcement.owner_command_reason` also denies agents the keychain item (`security ... -generic-password`, `security -i`), `budget.py init-key` and `owner_key`. Open item: `cloud/run_cluster.py <config> sign` signs on the worker, which has no keychain, so owner sign-offs of cloud runs are refused until a follow-up adds prepare-on-worker, sign-on-laptop. Self-tests OK1-OK13, OS1-OS5 (scope_signoff, stage_machine), OSG0-OSG5, OSK2, and budget BK3c updated. Smoke markers: `decision_spec.signoff.json:owner_signature`, `run_state.json~"owner_signature": "signed"`, and `scope_signoff.json~owner_signature` when a scope item is answered.
