## Changelog

**Pipeline v1 refuses to start or resume (owner decision, 2026-11-20).** `scripts/lib/pipeline_id.py` gains `RETIRED` and one message, "pipeline v1 is retired (owner, 2026-11-20); use v2": `select(v1=True)`, `from_flags`/`from_command` with `--v1` and `identity("v1")` raise it, and `resume_conflict` returns it for a run recorded as v1 or, with no record, one without `run_state.json`. `main.py --v1` prints it and exits 2 before the preflight or any run; `--resume` of a v1 run exits 1 with it; the v1 dispatch (`_run_v1`) is gone, and the rest of v1's code stays until the delete PR. `cloud/run_cluster.py` refuses a `RunConfig(pipeline="v1")` when it is built and again in `pipeline_preflight`; `cloud/vm_job.py` refuses a `main.py --v1` command with the same message; `scripts/eval_suite.py run --pipeline` accepts only v2. The two v1 launch configs, `cloud/configs/smoke.py` and `cloud/configs/e7r9.py`, are deleted (they could only launch v1). Old run records still read `pipeline: v1` (`label`). CLAUDE.md, README.md and the `cloud-compute` skill no longer tell anyone to use `--v1`. v2's dispatch, launch flags and preflight are unchanged; `from_command` refuses a literal `main.py --v1` call first (before the command-substitution check) and otherwise classifies every command exactly as before; a command it cannot parse (a shell wrapper, `python -m main`) that mentions `--v1` is refused by `vm_job.retired_tree_problem` only when the shipped tree's main.py predates the retirement, since a retired tree's main.py refuses `--v1` itself (an earlier shell-parsing scan was replaced after three Codex rounds kept finding wrapper forms it missed or v2 commands it misread), and `main.run`, the lead session's entry, raises the message whatever identity a caller passes. `pipeline_id.retired_resume` is checked first on a `--resume` (before the eval-isolation check, so a v1 eval run says it is retired) and again inside `main_v2`, so a direct call never resumes or restamps a v1 run; the other resume rules keep their place after `--preflight-only`. A resume of a directory that does not exist says so. `eval_suite.launch_tree` reads the config with the pipeline the launch selects, not an inherited `EVAL_PIPELINE`. Tests PI2/PI25b/PI29b-c/PI33c-f/PI39/PI39c-d, PV4-PV7e, PV11b-e, RP4/RP6/RP6b, VP2b-g and S19p-t failed before the change (PV11b-d and PI29/PI36 were also tightened after a Codex review: they now assert the specific diagnostic).
