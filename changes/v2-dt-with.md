## Changelog

**A `parameter_value` decision test can hold companion engine parameters fixed with `with: {parameter: value}`.** Owner decision, 20 Nov. The companions are applied in every case of the test: the evaluation's parameters are the point values, then the companions, then the tested value. `schema` validates the field: a non-empty mapping of engine parameters other than the test's own, each a finite number. It also records the companion values in the parameter domain. Two helpers in `engine_parameters`, `companions` and `test_settings`, give every reader of what a test sets one view, so a companion value is treated as a tested value everywhere: `batch.test_value_ranges` widens the emulator design box to span it, `tested_boxes` makes a held spec value named as a companion a design input, and the posterior precondition checks it against the column's hard bounds. In `decision_tests.plan_test`, each companion must be an emulator input inside the design box, or the test is not run and says why; a case is an identity only when every companion is at its point value. `run_one` names the companions in the result's `varied` text and records them as `with`. Under `calibration.method: posterior` the planner does not run a test with companions, with the reason, because that refit would not hold them. A test without `with` behaves as before: same text, no `with` key, and the batch self-test's recorded design hash is reproduced. Tests written first and failing before the change: RPW1 to RPW5 in `run.py` and PC16c in `preconditions.py` (α-β). Codex's read-only review raised five P1s and three P2s. Four P1s were fixed, with their cases written first and failing (RPW6 to RPW9; γ-δ). First, a quoted number among a test's values counts again, as the runner converts it; the first version dropped it, which changed the design for such a spec without `with`. Second, the planner, not only the runner, refuses a test with companions under a posterior calibration, so the sign-off checks agree with the run; and the dossier's range test checked its companions (superseded in round 2). Third, a test with companions cannot carry a benchmark departure, because the companions alone could produce the benefit change the run credits to the departure. Fourth, `with` on any other test type is refused instead of ignored. The fifth P1 is not changed: a companion is admitted to the design box with the same tolerance as a tested value and as the emulator's own domain check, which predates this change. Of the P2s, the decision-test artifact's summary row now carries `with` (RPW10) and RPW1 covers NaN, infinity and an empty mapping (in RPW6). Not changed: the claims text does not render the companions, and a hard-bound message now prints tested values as floats. Codex round 2 raised six P1s, all fixed with their cases written first and failing (RPW9, RPW11 to RPW14; ε-ζ). The dossier's range test now refuses a test with companions outright, as a departure does, so sign-off never credits a conditional test. The run's departure verdict refuses a record that held companions, which covers a departure whose benchmark is in band and skips the pre-run check. A value that is not a number raises where a test's values are read, and a held spec value's box ignores a quoted value, both as before `with`. `with` on another test type is refused while the engine is still pending. The pre-sign critique does not count a test with companions as varying its parameter. In short, a test with companions is an extra, conditional test: it cannot stand in for a departure's test, a dossier range test or the critique's evidence that a parameter is varied. There was no third round.
