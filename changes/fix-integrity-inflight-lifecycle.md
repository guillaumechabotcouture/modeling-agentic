## Changelog

**Integrity record: false `artifact_tampered` from eval baseline 1, fixed at its causes; launcher refuses hidden eval material on disk.** Eval baseline 1 (main 7d471e5): measles_campaign ended `artifact_tampered` on two open violations, `figures/eda_0{1,2}_*.png.provenance.json`, and flu_vaccine logged 98 violations (all closed later by the harness rebuild). Root causes, confirmed from both runs' records: (1) measles: the modeler added `validate_figure` to its own `eda.py` and ran it at 04:38. The sidecars that run wrote matched `figures/*.provenance.json`, a glob the figures step declared then and narrowed at 04:39. Declarations were sticky and the harness never built those files, so nothing could ever close the violations. (2) flu: the modeler (04:10) and then the lead (05:02) ran a full `scripts/pipeline.py run <run_dir>` themselves, which writes every declared output in the real run directory outside the harness's run. Entries left in flight by calls the CLI moved to the background (no PostToolUse; the planner's `#16` in flu, the data agent's in measles) did not cause any violation: intents only ever explain. They mislabelled every event and kept a stopped agent's carve-out (the planner's `metadata.json`) valid for up to 15 minutes. Fixes: an in-flight call now ends at its PostToolUse, at the SDK's terminal task message for it (`TaskNotificationMessage` / `TaskUpdatedMessage`, matched through `TaskStartedMessage.tool_use_id`), at its agent's SubagentStop, or at session end. Each of these runs a check first. Sticky ownership now covers only what the harness built (its `harness_wrote` calls during a pipeline run, and `models/pipeline_state.json`). When the record reads a declaration that narrows or retires a glob (never by a timer), it closes open violations on files only that glob held and the harness never built as advisories (`resolved.by: declaration_retired`), and lists the change in `declaration_changes`. Such a file is never marked harness-written: declared again, it is baselined and its step is stale, so the gate reports `pipeline_outputs_stale` until the harness builds it. A full `scripts/pipeline.py run <run_dir>` from any agent is refused at PreToolUse; the refusal lists the allowed forms (`--scratch`, `--dry-run`, `validate`, or asking the lead). Separately, `cloud/run_cluster.py launch` refuses a tree holding hidden eval material on disk (`_truth*`, `*.enc`, decrypted bundles, generators, rubrics, any untracked file under `evals/`; `eval_paths.tree_hidden_material`), because Coiled package sync uploads untracked and ignored files. Tests: `agents/integrity.py --self-test` IG1-IG10 (IG1 replays the measles record from `tests/fixtures/integrity_measles_evalbase1.json`), main.py IN10-IN12, eval_paths EP12, run_cluster RC50d-f. Retro: replaying the measles events on a copy of the real run, main ends `artifact_tampered` and this branch ends `completed_gate_not_accepted` (the gate's own verdict). On flu, the new rule refuses the modeler's and the lead's two full-build calls.
