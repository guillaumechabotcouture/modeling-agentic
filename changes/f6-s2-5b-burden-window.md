## Changelog

**Burden validation over past years, report-only rows and rows with no published interval (F6 S2-5b).** Three gaps a real spec draft found in `validation.burden` (#165). (c) The model value was always the arm's mean over the decision window, which lies in the future, while a reference describes observed past years. A block may now declare `window: [start, end]` (inside the simulated `horizon`) with `window_metrics: {outcome: {population group: <engine window metric>}}`, the engine window metric that gives each compared outcome per person of that `decision_units.populations` group over a named window (a single metric for an outcome is accepted only when one population group spans the engine's age groups, so the window value is weighted by the spec's populations as the decision-window value is). The harness adds the window to the engine's named windows (`Horizon.windows`, `burden_validation`) in the runs it already makes, so no run is added: each run returns the engine's window metrics for one more window, and on the emulator path one more Gaussian process per mapped outcome and population group is fitted. The model value is the sum over population groups of the arm's window metric times the group's population, averaged over the window years; the draws give its interval as before, and on the emulator path the emulator error reaches the window values as a column of its error model. A stored batch whose design records another burden window is refused at adoption, and the gate refuses an artifact whose arm, window or window metrics differ from the signed spec. The year-gap check compares the reference year with the model window. Every reference's outcome needs a window metric, and age-banded rows are refused under a window (window metrics are all ages). Engines accumulate per-person outcomes only over the decision window, so an outcome without a window metric (for the malaria engine, only clinical cases have window metrics, `inc_all` for all ages and `inc_u5` under 5; deaths and DALYs have none) cannot use a past window until the engine reports it per named window. A spec without `window` produces the same engine windows and batch job hashes as before; a spec that adds one changes its batch job hashes, so a batch computed without it is not reused. (a) An optional `role` column (`checked`, the default, or `report_only`): report-only rows are computed, judged and shown beside the checked rows, and never produce a finding (outside tolerance or unmatched; an unmatched row is still recorded as such); at least one checked estimated row is required. (b) An optional `interval` column (`published`, the default, or `none`): with `none`, lower and upper are left blank, the row is judged on its ratio band alone (overlap is refused), and the finding text and `results.md` say "no published interval". Role, interval and window are part of each row's declared metadata, which the gate checks against the signed spec; the sign-off sheet shows the model window and its metrics, and signing still hashes the whole reference file. `results.md` lists the report-only rows, the claims ledger gains a `role` claim per row (and no lower or upper claim for a row with no published interval), and the figure marks report-only rows. The DALY parts stay over the decision window, and say so. Self-tests: `burden.py` BV29–BV40 (a toy engine whose rate triples at the decision window: the past-window mean is 1 per person-year, the decision-window mean 3), `run.py` BE8–BE10 (the emulator path).
