## Changelog

**v2 is the default pipeline; every run, launch record and score names its pipeline and commit; smokes check markers.** On 2026-11-05 an eval re-run meant to test a v2 fix ran the v1 pipeline: `main.py` defaulted to v1, `cloud/configs/_eval.py` never passed `--v2`, so the standard eval launcher had always run v1, and nothing recorded or checked which pipeline a run used (about US$28 spent; eval scores from that launcher are v1 scores). Owner decision the same day: v2 default, pipeline explicit, recorded and asserted everywhere, and smokes that prove the changed code ran. `scripts/lib/pipeline_id.py` is the one answer to "which pipeline": v2 unless `--v1`, `--v2` a no-op alias, both refused; it writes `pipeline`, `commit` and `launcher` (and one `invocations` entry per start or resume) into `metadata.json` before either pipeline starts. A launch tarball knows its commit through `scripts/lib/code_commit.txt` (export-subst). A run recorded under one pipeline is not resumed under the other; v1's end-of-run restore protects the identity fields; `stage_machine.init_run` merges `metadata.json` instead of replacing it. `cloud/run_cluster.py`: configs declare `pipeline=` (flags may not carry `--v1`/`--v2`); the launcher passes it explicitly with `--launcher run_cluster:<name>`, and `pipeline_preflight` asks the shipped `pipeline_id.py` (run isolated from the tarball) which pipeline those arguments run before anything is created, refusing a missing declaration, a tree that cannot answer (any tree from before this change) or a disagreement. `assignments.json` and each collected `result.json` record pipeline, commit and launcher, plus the run's own identity. Configs: `eval_*` v2 (`EVAL_PIPELINE`, default v2), `nigeria_gf13_v2` v2, `e7r9` and `smoke` v1, stated. `cloud/vm_job.py` refuses a `main.py` command without `--v1`/`--v2`, sets `MA_LAUNCHER`, and writes a launch record in the grader's format (`assignments.json` + `result.json`, `eval_inputs_sha256`), so such a run is graded without `--unverified-inputs`. `scripts/eval_suite.py` prints pipeline and commit with every score, refuses a run whose recorded identity is not its launch's (`pipeline_mismatch`, `pipeline_unrecorded`, `commit_mismatch`), and `report` refuses to compare score files from different or unknown pipelines without `--allow-mixed-pipelines`; old runs read `unknown`. `scripts/smoke_check.py` fails a smoke run that lacks the markers its PR names (`PATH`, `PATH:KEY`, `PATH:KEY=VALUE`, `PATH:KEY^=PREFIX`, `PATH~REGEX`); CLAUDE.md "How to verify" asks each run-behaviour PR to name them. Self-tests PV1-9 and EV4 (`main.py`), RP1-13 (`run_cluster.py`), S19 (`eval_suite.py`) and VP1-6 (`vm_job.py`) were written first and failed before the change; PI1-28 (`pipeline_id.py`) and SC1-9 (`smoke_check.py`) cover the new modules.
