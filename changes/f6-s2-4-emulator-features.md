## Changelog

**Emulator features from engine unit attributes, and emulator error on every emulated quantity the decision uses (F6 S2-4 part 1).** Two gaps of critique finding C5. (1) `analysis.emulator.features` took only numeric units-table columns, so a unit's seasonal profile, its past intervention years, rounds or coverage, or a past product type could not be an emulator input. An entry may now be `{attribute, encoding[, value][, empty]}`, naming an attribute bound in `decision_units.engine_attributes` (the value the unit's engine runs get) and how it becomes one number (`toolkit/analysis/features.py`): `value` (a number); `count`, `sum`, `mean`, `sd`, `min`, `max`, `first`, `last` (a list of numbers; an empty list gives 0 for count and sum and takes the declared `empty` number otherwise); `harmonic_cos`, `harmonic_sin`, `harmonic_amplitude` (a list read as one cycle: its first harmonic relative to its mean, so a seasonal profile's peak timing and strength are two continuous inputs, zero for a flat profile); `equals` (an indicator of one category). The schema refuses an unknown attribute or encoding, the calibrated attribute, a value the encoding cannot read for any unit (text, a mapping, a non-finite number, an empty list without `empty`), misplaced keys and duplicate names. A column entry works as before. Features are emulator inputs only: the design and every batch job hash are unchanged by them, so a stored batch is reused when features are added or removed. The design-coverage figure plots encoded features. (2) The emulator error drawn in the uncertainty step covered only the package reductions. Its error model now has a held-out residual column for the comparator burden (log scale, per population group and outcome) and for each cost output per package (the emulated cost drivers, e.g. treated cases), beside the reductions and the burden-window values. Every column is drawn from the same held-out residual rows (a common part plus a per-unit part, as before), so a unit's comparator, reduction and cost errors keep the correlation they show at the held-out points; the assumption, stated in the error model's summary, is that this correlation holds at the units' own inputs. Adding columns leaves the reduction errors' draws as they were (the same random numbers per draw). A cost value pushed below zero by the drawn error is floored and counted (`emulator_error_floors` in `analysis/uncertainty.yaml`), not reported as a model correction; the summary counts columns by quantity and reports the median comparator–reduction residual correlation. Without features, the design, job hashes, point estimates and every artifact except the uncertainty draws are unchanged; the uncertainty intervals of an emulator-path run that draws the emulator source now include comparator and cost error. Self-tests: `features.py` FT1–FT9, `model.py` ME6–ME9 and EM1–EM6 (toy engine: features do not move the design or the job hashes; the drawn error moves comparator burden and cost outputs), `run.py` RP9 and RP9b.
