## Changelog

**One validated snapshot of benchmark evidence (F6 S1-2b, Codex round 4 on #154 and round 1 on #158).** Threat model: stale or changed artifacts and declarations on disk, and code paths that read evidence without the loader; deliberate in-process mutation by harness code is out of scope. `load_evidence(engine, pack, rows, partial)` in `toolkit/engines/benchmark_sources.py` returns an `Evidence` snapshot: the validated pack, the fitted values the engine actually uses (cached or defaults) with the digest of the file behind them, and the stored rows. It stores deep copies and returns detached ones. Its problems are an unreadable or empty pack (absence is permitted only for an engine with no rows to check and no fitted values to back); the source check; missing rows and rows with no digest or another declaration's digest ("rerun required"); and fitted values without current provenance ("refit required"), including a fit made under another engine revision: the fitted document must carry the runner's stamp with the current engine name, version, code and configured structure (the stamp's pre-fit parameter identity is not compared). The snapshot carries the fitted document parsed from the bytes it hashed; the `run` CLI passes it to `reach_check` and `render_notes` renders it, with no reread. Every estimand type's declaration digest covers its band and source fields, estimand, arms, settings, configurations, horizon, seeds and engine, the pack's `coverage_scoring`, the code of its oracle and calibrator modules and, for oracle and coverage checks, the observation code and `analysis/thresholds.yaml`. Coverage rows are also checked on their own declaration and calibration-code digests. There is no legacy acceptance. An explicit pack is bound to the supplied engine's class, and the toy exemption comes from that binding. `Runner` scores only clean evidence and only with its fitted values; candidate fitted values need the explicit fit mode (the fit CLI, joint calibration, the `b15_mechanisms` scan), and `reach_check` uses `evaluate_at`. `Runner` keeps its own copy of the validated pack and `evaluate()` resolves each benchmark by id. `spec_benchmarks` scores with the evidence it validated. Only exact registered self-test toys are exempt, not their subclasses. Routed through the snapshot: `Runner` and `run_pack`; `verified_benchmarks`, merge, rescore and the `run` and `fit` CLI; `fitted_ranges`, and through it core, the batch design, joint calibration's `build()` (which now uses the captured values) and the emulator box; the analysis entry; joint calibration's `_benchmarks()`; `spec_benchmarks`, `verified_spec_benchmarks` and the `engine_parameters benchmarks` CLI; estimates acceptance, which reads the snapshot's pack and rows; `render_notes.write()`, which renders only a results envelope validated through `verified_results` (engine identity, fitted values in use, configuration and the snapshot's rows) and the fitted document parsed from the bytes the snapshot hashed; and `b15_mechanisms`. Not routed: `render_notes.render()`, a formatter of what `write()` passes it; the engines' `describe()`, which reads stored rows for the card (engine directories unchanged, so code fingerprints stay valid); the malaria diagnostic and proof scripts (`runtime`, `guess_sensitivity`, `equilibration`, `restamp_proof`); and `spike/`. Self-tests BS54–BS69 include behavioural bypass tests on self-contained stale fixtures. The compartmental and renewal packs were rerun locally (2 workers) to stamp their results with digests. Every row reproduces the stored values and verdicts to a relative 1e-9. The malaria artifacts report refit and rerun required.
