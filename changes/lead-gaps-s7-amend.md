## Changelog

**Under `--signoff lead`, a rethink of a signed spec (S7) is amended provisionally instead of pausing (closes the second known limit of 1F, #316).** The fix planner wrote a SPEC rethink as prose only, so S7 always paused `awaiting_spec_amendment`, also in an unattended lead run. `FIX_PLANNER_PROMPT` now asks a SPEC rethink for a machine-readable `patch` in `toolkit/spec/amend.py`'s format (`id`, `reason`, `spec` operations `set` / `add` / `remove` by dotted path or `[key=value]`). `fix_loop.spec_patch` reads the patch of the rethink the loop routes, and `rethink_request` writes it into `spec_rethink_request.json` under `--signoff lead` only, so an owner's `amend --from-request --patch` is unaffected. Under `--signoff lead` only, `h_SPEC` then calls `Machine._lead_amend`. It runs `amend --from-request` on the paused parent, which makes a child run (`<run>.amend<k>`) with all of amend's checks. The lead signs the child's spec, marked provisional in the note, with the hashes the dry-sign used. The child resumes at SIGN, not paused, with what is left of the parent's cap. The parent ends `amended_provisional` (`amended_to` in its history; exit 2; the child's `parent_run` re-bound to the parent's final state). `run_v2` continues in the child in the same process (`handoff_child`; `tasks.for_run_dir`; the parent's pipeline identity stamped on the child), and `main.py` stores every child with the run (`handoff_chain`). The child's `report.md` lists the amendment first (`amendment_lines`: id, reason, changes) as provisional. A lead-signed spec cannot be re-signed in place, so the owner confirms by amending the parent with the same patch, which is still in its request (`python3 -m toolkit.spec.amend <parent> --from-request --signoff owner`). That child's spec is byte-identical to the lead's, and the owner signs it. An owner-signed amendment is not flagged. Under `--signoff owner` nothing changes: the run pauses for the owner. The run also pauses as before, and the refusal is recorded in the request (`lead_amendment`), in these cases: no patch (including a GATE → SPEC structural rethink, which has no fix plan), a patch that does not apply or validate, an amended spec that would not sign, a run that is itself a provisional amendment (no second one without the owner), the parent's sign-off no longer holding, no budget left (a zero cap is never passed on as unlimited), or an earlier refusal (kept with its reason on resume). Codex round 1: the child's path is recorded (`started`) before amend makes it, so a handoff interrupted after signing is finished on resume with the same child, never repeated; a moved or restored parent resolves its child beside it and only when the child's `parent_run` names it; a child that loses `amendment_record.json` still heads its report as provisional and refuses a second lead amendment, using the handoff event in its history; the record is harness-owned, so no deliverable can overwrite it; a child kept after a signing refusal is stored with the run (`handoff_chain(kept=True)`); a manual `amend --patch` signed by the lead gets its own wording. Codex round 2: the budget check uses the rounded balance the child receives; the child's state (not paused, the balance, the handoff event) is written before the lead's signature, so a signed child always says it is provisional; recovery resolves the recorded child beside the parent and refuses, with a reason, when its state cannot be read; a finished parent resumes a sibling only when the child binds that parent's final state (`run_state_sha256`) and is not the run itself; the handoff chain in `run_v2` is bounded. Known limits: two processes resuming the same parent at once are not locked against each other; the lead's check of the parent's signature covers the spec sign-off, not a legacy decision-brief signature over other files; resuming through the parent with a higher `--max-budget-usd` does not raise the child's cap (resume the child itself); a parent with an open HIGH finding that amend imports as an undisposed review condition fails the dry-sign and pauses. Self-tests F_PATCH1-F_PATCH2 (`agents/fix_loop.py`), S_FOR_RUN_DIR (`agents/v2_sdk_tasks.py`), T_LEAD_AMEND, T_LEAD_AMEND_CHILD, T_LEAD_AMEND_LINK, T_LEAD_AMEND_REPORT, T_LEAD_AMEND_HANDOFF, T_LEAD_AMEND_OWNER, T_LEAD_AMEND_PAUSE, T_LEAD_AMEND_REPLAY, T_LEAD_AMEND_BUDGET, T_LEAD_AMEND_RESUME, T_LEAD_AMEND_MOVED, T_LEAD_AMEND_STRICT, T_LEAD_AMEND_LOST (`agents/stage_machine.py`).
