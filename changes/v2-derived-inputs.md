## Changelog

**Harness-run derivations for the spec's data (v2-derived-inputs α-δ; design note `docs/design/v2-derived-inputs.md`, PR #113).** The planner task writes code, never tables. It declares each derived file in `data/derivations.yaml` (script under `data/derive/`, staged inputs, outputs under `data/derived/`, column accounting). `scripts/pipeline.py derive` runs each script in a sandbox: bubblewrap with every namespace unshared, the run directory hidden, inputs bound read-only, a private work directory, caps on memory, CPU time, file size and processes, a wall-clock timeout, a minimal environment and an import allowlist (the standard library, numpy, pandas and pyyaml, checked by an AST scan). It runs each script twice and, when the declaration ignores columns, once more with them removed. It records script, input and output hashes, the sandbox and library versions in `data/derivations_record.json`. It reuses the pipeline's DAG ordering (`_toposort`, now shared with `load`), hashing and environment filter. New codes, all HIGH: `units_not_derived`, `data_ref_not_derived`, `derivation_stale`, `derivation_failed`, `derivation_nondeterministic`, `derivation_unsandboxed`, `input_column_unaccounted` (HIGH by owner decision) and `ignored_column_used`. `h_SPEC` runs the draft, the derivations, `record_cited_inputs` (now on the shared `cited_paths` walk) and the full pre-sign checks; problems go back to the planner with the script's stderr. `data/derived/` is a harness prefix, and `draft_spec` owns only `data/derive/`, `data/derivations.yaml` and `data/README.md`. Engine cards gain `attribute_binding.yaml` (malaria, compartmental, empirical, toy). Card metadata only: code fingerprints and benchmark stamps are unchanged. Every attribute is bound, calibrated or accepted by name (`decision_units.defaults_accepted`): `engine_attribute_unbound`, `attribute_column_empty`. `prior_target_not_parameter` covers `uncertainty.priors`, `calibration.priors` and card priors, and `target_frame_unmapped` covers the calibration target's frame. Bug fixed: with `engine: auto`, `pre_sign_problems` ran only the engine-independent sections; it now runs the full checks per card-eligible candidate before SIGN. A failing candidate is ineligible, with its reasons, in the sign-off sheet and in `engine_choice.json`. The spec is refused only when no candidate passes. The sign-off freezes the derivation record and the derived files it lists. The new sign-off sheet (`decision_spec.signoff_sheet.md`, `signoff.py sheet`) lists the accepted defaults with their card meaning, the ignored columns and tables, and the candidates. macOS fails closed; `--dev-unsandboxed-derivations` runs derivations unsandboxed and leaves a HIGH non-declarable gate finding. Tests DI1-DI13 in the self-tests of `scripts/pipeline.py`, `toolkit/spec/{schema,priors,signoff}.py`, `agents/stage_machine.py` and `agents/v2_sdk_tasks.py`. The Linux sandbox tests (DI2-DI5) ran on a Coiled VM. Its container's host forbids unprivileged user namespaces, so the sandbox there is started through `sudo -n bwrap` and runs as the run's own user. The retro DI14 on the 2026-11-01 run is in the PR (counts only).
