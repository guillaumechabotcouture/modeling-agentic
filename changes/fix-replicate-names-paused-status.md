## Changelog

**One stored run per replicate; every pause and crash recorded in metadata.json.** Baseline hb3 lost one replicate's records: two replicates of one launch started in the same second, took the same run dir name (`main.py` checks for a clash only on its own VM) and the same blob, `outputs/<prefix>/<run dir>.tar.gz`, and the second upload overwrote the first. Now `cloud/worker_side.run_job_impl` tells `main.py` its label and launch (`$MA_RUN_LABEL`, `$MA_LAUNCH_ID`): the run dir name ends in the label, `metadata.json` records `run_label` and `launch_id`, and `agents/run_finish.py` stores the run at `outputs/<prefix>/launch_<id>/run_<label>_<run dir>.tar.gz`. A run with neither keeps the earlier name. No store overwrites another run's blob: `results_store.upload(..., overwrite=False)` is refused atomically by Azure, and the same bytes already there count as this upload, landed on an earlier try. Other bytes raise `BlobNameTaken`, which is not retried. The run is then stored under a fresh suffixed name, recorded in `store_collision`. Only a run storing itself again (a resume: `metadata.json` `stored` names the blob) replaces its blob. `run_cluster.collect_from_storage` refuses (`StoredRunRefused`) a stored run whose `metadata.json` records another label, or, when it records none (runs stored before this change), whose blob another label's record of the launch also names. Nothing is extracted then. `collect` and the supervisor's fetch pass the launch's labels, and `collect` falls back to the label's own VM copy. Old stored names stay readable through each record's `run_stored`. The supervisor archives per launch, at `collected/<launch>/launch_<id>/<label>.tar.gz`. A paused v2 run (hb3 flu R1, ANALYZE to SPEC after a calibration refusal) exited 2 with no status in `metadata.json`, because only FINAL wrote one. `Machine.run()` now records `status: paused:<reason>` with `paused_state` and `paused_why`: the reason the run entered its state, a budget pause's allowance, and the lead's refusal of an amendment. It removes `finished`, and the next pause or `_finish` replaces it (`_finish` drops the pause fields). `main.run_v2_and_store` records `crashed` or `interrupted` beside `crash` when a run ends by an exception, unless the machine already wrote a terminal status. `scripts/harness_metrics.py` counts a run whose `metadata.json` pause disagrees with `run_state.json` as `status_mismatch`. Self-tests SN1-3, RD1, SC (main), S28 (results_store), UN1-5 (run_cluster), SV10b-c (supervisor), PS1-4 (stage_machine), HM18b-c (harness_metrics).
