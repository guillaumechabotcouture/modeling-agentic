## Changelog

**One stored run per replicate; every pause and crash recorded in metadata.json.** Baseline hb3 lost one replicate's records: two replicates of one launch started in the same second, took the same run dir name (`main.py` checks for a clash only on its own VM) and the same blob, `outputs/<prefix>/<run dir>.tar.gz`, and the second upload overwrote the first. Now `cloud/worker_side.run_job_impl` tells `main.py` its label and launch (`$MA_RUN_LABEL`, `$MA_LAUNCH_ID`). The run dir name ends in the label. `metadata.json` records `run_label` and `launch_id`, and `pipeline_id.stamp` updates them on a resume and in an amendment's child. `agents/run_finish.py` stores the run at `outputs/<prefix>/launch_<id>/run_<label>_<run dir>.tar.gz`; a run with neither variable keeps the earlier name. No store overwrites another run's blob: `results_store.upload(..., overwrite=False)` is refused atomically by Azure, and the same bytes already there count as this upload, landed on an earlier try. Other bytes raise `BlobNameTaken`, which is not retried. The run is then stored under a fresh suffixed name, recorded in `store_collision`, and keeps that name when it resumes. Only a run storing itself again, in the same account (`metadata.json` `stored`, `stored_account`), replaces its blob. `run_cluster.collect_from_storage` refuses (`StoredRunRefused`) three kinds of stored run, and extracts nothing from them: one whose `metadata.json` records another label; one that records another launch; and one that records no label (runs stored before this change) whose blob another label's record of the launch also names. It stops on a sibling record it cannot read. `collect` and the supervisor's fetch pass the launch's labels. After a refusal, `collect` falls back to the label's own VM copy and counts that copy's omitted large files as unstored. Old stored names stay readable through each record's `run_stored`. The supervisor archives per launch, at `collected/<launch>/launch_<id>/<label>.tar.gz`. A paused v2 run (hb3 flu R1, ANALYZE to SPEC after a calibration refusal) exited 2 with no status in `metadata.json`, because only FINAL wrote one. `Machine.run()` now records `status: paused:<reason>` with `paused_state` and `paused_why`: the reason the run entered its state, a budget pause's allowance, and the lead's refusal of an amendment. It reads `metadata.json` without following links and removes `finished`; the next pause or `_finish` replaces the record, and `_finish` drops the pause fields. `main.run_v2_and_store` records `crashed` or `interrupted`, with `crash` and `crashed_at`, when a run ends by an exception. It writes them in the chain's last run, and replaces any status but a terminal one written in this invocation. `scripts/harness_metrics.py` counts `crashed` and `interrupted` (dropped after a cut-off), and counts a run whose `metadata.json` pause disagrees with `run_state.json` as `status_mismatch`. That check uses the files as they are, so it never changes a result at an earlier cut-off. Self-tests SN1-5, RD1, SC (main), PI19b (pipeline_id), S28 (results_store), UN1-7 (run_cluster), SV10b-c (supervisor), PS1-4 (stage_machine), HM18b-d (harness_metrics).
