## Changelog

**One calibration scale default, taken from the engine card; a log scale refused for an attribute that goes below 0.** `toolkit/analysis/batch.py` `calibrated_value` read an undeclared `calibration.scale` as `log` while `toolkit/spec/schema.py` documented `linear`, so a spec calibrating `log_rate` on [-8, 2] with no scale gave the engine `exp(z) > 0` as a log rate: an impossible fit that ran into the bound and was refused as a ridge. `schema.calibration_scale` is now the one resolution (the declared scale; else the engine card's valid range for the attribute: a range going below 0 means linear, one from 0 up keeps log; else linear), read through `Spec.calibration_scale()` (cache keyed on attribute and engine, a failed card read never cached) or `schema.resolved_scale` for a raw mapping (the named engine's card read), by the batch, the joint calibration (problem and signature) and the figure-data rebuild check; an attribute on a range from 0 up (a transmission density, a share, a seed) keeps its log scale and its job hashes. Before sign-off, `scale_problems` refuses a declared log scale for an attribute whose card range includes negative values, with the reason (a range from 0 up is accepted: exp(z) reaches as close to 0 as the range asks), on the likelihood/emulator and observed-targets paths, and an explicit `scale: null` is refused instead of read as the default. `toolkit/analysis/calibration.py` is unchanged: its bytes are bound to the compartmental coverage pack (`benchmark.calibrator_code_digest`), so naming bound parameters in the ridge refusal is left to a change that re-runs that pack. `analysis/blocked.yaml` already records a refusal's `at_bound` when the exception carries it (none does yet). Self-tests BA-SC1 (the toy panel with its scale removed now calibrates with no parameter at a bound) and SP4s-x (the resolver, raw and Spec alike, the pre-sign refusal, a null scale, a log scale on a range from 0 up) failed before the fix.
