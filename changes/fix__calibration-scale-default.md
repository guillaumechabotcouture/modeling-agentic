## Changelog

**One calibration scale, resolved and checked in one place, taken from the engine card when undeclared; a log scale refused for an attribute that goes below 0.** `toolkit/analysis/batch.py` `calibrated_value` read an undeclared `calibration.scale` as `log` while `toolkit/spec/schema.py` documented `linear`, so a spec calibrating `log_rate` on [-8, 2] with no scale gave the engine `exp(z) > 0` as a log rate: an impossible fit that ran into the bound and was refused as a ridge. `schema.check_scale` is now the one resolution and check: the declared scale (anything but log or linear, an explicit null included, is refused); else what the engine card's valid range for the attribute implies (a range going below 0, -inf included, means linear; one from 0 up keeps log; no range: linear); else, with no engine named, linear. It refuses, never falls back: a log scale on a card range going below 0, candidate engines whose cards imply different scales, and an engine card that cannot be read when the answer depends on it. `Spec.calibration_scale()` (an answer kept per attribute, declared scale and engine; a refusal never kept; `Spec.engine()` reloads when the spec's engine declaration changed) and `schema.resolved_scale` (any mapping, read-only ones included) raise `CalibrationScaleError` on a refusal; the batch, the joint calibration (problem and signature), the figure-data rebuild check and the results' attribute notes read the scale there. `schema.spec_scale_problems` runs the same check as the shared precondition `calibration_scale` (`toolkit/spec/preconditions.py`), so validation on every calibration method (method none included: the emulator design consumes the attribute) and every signing entry point run it; with `engine: auto` it reads every engine the selection may pick, each built with the configuration the selection gives it (`agents/analysis_backend.py` candidate_entries; one whose card cannot be read that way or that lacks the attribute is never picked and is left out, none left refuses), also once an engine choice is written (the signature covers `engine: auto`); the standalone joint calibration's `spec_problems` runs it too and reports an unreadable card instead of raising. An attribute on a range from 0 up keeps its log scale and its job hashes. `toolkit/analysis/calibration.py` is unchanged (its bytes are bound to the compartmental coverage pack); `analysis/blocked.yaml` records a refusal's `at_bound` only when the exception carries it (none does yet). The edit to `batch.py` changes `joint_calibration.adapter_digest`, so stored rows stamped with the previous digest are not reused. Self-tests BA-SC1 (the toy panel with its scale removed calibrates, converged, with no parameter at a bound), SP4s-aj, SP4t2, AB3c, JA-SC, JA-SC2 and RUN_BLOCKED_AB failed before the fix.
