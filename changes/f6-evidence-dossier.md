## Changelog

**No sign-off until every input that drives an option's effect has a checked, sourced evidence entry (owner decision 2026-11-12).** Runs reached paid compute with decision-moving inputs nobody had checked against field data, and the post-hoc gates, which check internal consistency, passed. This is a precondition, not another gate. Each engine card declares its `decision_inputs`: per package component, the unit attributes, engine parameters and card tables its effect depends on, with the values that have no effect (`toolkit/engines/decision_inputs.py`). The declarations live in a `decision_inputs.yaml` beside each card (malaria, compartmental, renewal, package-rate), merged with any `decision_inputs` key in card.yaml. They are kept out of code and out of `contract.py`, whose bytes are in every engine's code fingerprint, so no stamped benchmark result goes stale. A spec names its run's dossier (`evidence: {dossier: evidence_dossier.yaml}`). Each entry gives the model value and its source; then either field or trial observations (source, URL or table, year, sites, n, sampling frame, value) with a comparison, or an explicit `no_data` with its borrowing rule; then the chosen value or range, its rule, and the decision test for a range (`toolkit/spec/evidence_dossier.py`). `toolkit/spec/signoff.py` refuses to sign, whoever signs, when the dossier is missing, unparseable, blank anywhere or missing an input of a component the options use (for `engine: auto`, of every eligible engine), and it lists what is missing. It also refuses when an engine cannot map a component (fail closed). The sheet renders the dossier table, records its sha256 in its sources, and the signature binds it, so an edit after sign-off makes the status `changed`. `cloud/run_cluster.py stale_sheet_problems` refuses a launch whose shipped dossier differs from the one the sheet recorded (at SIGN) or the sign-off recorded (past SIGN). A spec whose options use no component with declared inputs needs no dossier. After review round 1, every signing path (`scripts/decision_brief.py` and `agents/stage_machine.py` too) goes through the same `evidence_dossier.bind`. The inputs the options need decide whether a dossier is required, not whether the spec names one, and a sign-off made before this requirement, of a spec that needs a dossier, is `unsigned_evidence`. Past SIGN, the launch requires the shipped spec to match its signed hash, while SPEC drafts are not checked. ENGINE_CHOICE re-checks the dossier against the engine it picks, and `engine: auto` uses the backend's full eligibility. Malformed declarations and missing `engine_map` entries fail closed. Blank checks recurse into nested values, and text fields must be text. A range's decision test must vary that input over the range. Configured engines resolve their inputs against the configured card (`if_on_card`, globs), and every card parameter and unit attribute is either a declared input or excluded with a reason (`not_decision_inputs`, checked by ED-E3). Review round 2: the brief's signer recomputes the binding and refuses a supplied one that differs, and refuses a dossier changed after the sheet. `prior_range_<p>` counts only for a prior the draw plan draws (`priors.drawn`). A value the spec runs (`engine_parameters` or a unit attribute bound to a value) must match the dossier's model and chosen values, or lie in its chosen range. Outcome-level inputs (`outcome_inputs`) are required whenever the primary or headline outcome uses them, whatever the components: malaria treatment, severe-care fatality and DALY inputs, and compartmental outcome ratios.
