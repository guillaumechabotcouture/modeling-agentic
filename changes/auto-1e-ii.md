## Changelog

**Liveness: the agent VM's heartbeat record, preparing and dead, status isolation, attach by id.** `cloud/worker_side.py` `run_to_disk` starts a liveness record (`RunState`, `<work root>/.state_<label>.json`: phase, pid, start and update times) before pip and unpacking and rewrites it every 30 s; phases are preparing, running, storing, held, done and failed. `fetch_meta` reads it: a VM still installing reads `preparing` (it read `missing`, which the watch relaunches), and a task that ended without a result, lost its process or has not rewritten the record for 180 s reads `dead` (it read `running` for good); without a record the answer is as before. `cloud/run_cluster.py`: `status` prints `unknown` for a label whose VM cannot be read and goes on to the others, and shows the phase and heartbeat age; `status`, `collect`, `relaunch`, `keeper-log` and the `*_side` calls connect through `existing_client` (`connect_existing`, which cannot create a cluster) and `shutdown` stops each live cluster by id, so no path attaches by name any more; `relaunch` refuses a preparing or dead label; `run_job_impl` records `unstored_large_files` and `collect` keeps a label pending (no `result.json`, not marked collected, no shutdown) while large files exist only on its VM, until `collect --accept-partial`. `cloud/launch_watch.py`: `parse_status` reads the keeper's state, and the watch logs one notice for a dead run and one for a stopped keeper; it stops and relaunches nothing for either. Self-tests: `run_cluster.py` LV1–LV9, `launch_watch.py` LW7c–e. Not in this change: `keeper_later` still reserves (the audit marks it partly fixed and BU5/BU7d assert it); releasing a reservation on a failed construction and caching stopped-cluster costs in `cloud/budget.py`; no dollar-based stop is added.
