## Changelog

**An owner-signed cloud budget and its measured spend (F6 S2-BG1).** On 2026-11-11 an agent operating this repo spent $106 of the owner's $100 cloud budget. The budget, the dollar conversion and the spend checks lived in the agent's memory and judgment. New `cloud/budget.py` puts them in code. It guards against the agent's mistakes and forgetfulness, not deliberate circumvention: a bypass needs an edit visible in git, which is out of scope. The budget is a record signed with an Ed25519 key. The record holds scope, usd, start_utc, note, issued_utc, expires_utc (default 14 days, `--days` at most 60), nonce, and the scope's cluster-name prefixes and floor from `cloud/budget_scopes.yaml`. `budget.py init-key` passes `add-generic-password -s modeling-agentic-budget-owner -a owner -l modeling-agentic-budget-owner-key -T "" -w <key>` to `security -i` on stdin, so the key never appears on a command line. The keychain item trusts no application, so every read raises the owner's keychain password dialog. The public key goes to the tracked `cloud/budget_owner.pub`, which the owner commits. `set --scope --usd --note [--start] [--days]` shows the record on the terminal and asks the owner to type its amount (`/dev/tty`). Only then does one signing call read the key into a buffer, sign exactly that record and zero the buffer. The call never returns or stores the key. Residual: copies made inside Python and `cryptography` cannot be zeroed. The record goes to `~/.config/modeling-agentic/budget_<scope>.json`. These are refused: a bad signature, a changed field, a missing or unparsable file, an expired record, and a record older than the newest one seen for its scope, or with the same issued time and another nonce. The newest-seen mark is the local `budget_<scope>.seen` file, which catches mistakes but is not tamper-proof. Spend covers every cluster in the IDM workspace that has a signed prefix and ran inside the window. Billed USD = `total_cost` x 0.061 + `cloud_total_cost` from the raw cluster record (coiled 1.135.6 `CloudV2._get_cluster_details_synced`, `coiled/v2/core.py:976`). Each cluster counts max(billed, the sum of its instances' hours in the window x max(the scope's median USD per instance-hour over its last five stopped clusters, the VM type's upper bound in the new `cloud/vm_prices.yaml`)). That table covers the Dv5, Dsv5, Dasv5, Esv5, Easv5 and Edsv5 families from 2 to 96 vCPU. Each bound = Azure list price x 1.25 + vCPU x 1.5 credits x $0.061. Our own records support these constants: the P6 cluster (25 x Standard_E8s_v5 + 1 x Standard_D2_v5, about 2.6 h) billed 510.3 credits, about 1.0 per vCPU-hour, and $32.11 cloud cost, about list price x hours. Instances are counted from instance states, so an errored cluster with live VMs counts. A cluster created before the start counts from the start. These refuse: an unknown VM type, missing scheduler, worker or instance data, a missing or negative cost, and a budget that starts in the future. `launch_budget_ok(scope, cap_usd, name, reserve=True)` takes no injection. Under an exclusive lock it records a reservation of the cap, which counts until a cluster of that name appears, or for 2 h (concurrent launches from this machine only). `job_meter(scope)` reads one cluster's USD by id. `show` and `status` print the record and the spend. Self-tests BK1-BK6 and BR7-BR18 were written first and failed before the change. BR18 checks that every VM type named in `cloud/`, its configs and `scripts/compute.py` has a bound, and so does every type seen on our clusters (Standard_D2_v5, Standard_E8s_v5, Standard_D32_v5, Standard_D64_v5) and every vm_job `--cpu` size. They use generated keys, a fake key store and keychain runner, and a fake Coiled source.
