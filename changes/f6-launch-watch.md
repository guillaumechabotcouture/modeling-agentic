## Changelog

**A tracked launch watchdog (F6 S2-LW).** The F5 launches were watched by a local, untracked bash script with the config's names written into it, and launched through a hold wrapper made obsolete by S1-8 (its patch of `run_cluster._submit` had the wrong signature). `cloud/launch_watch.py <config>` replaces both, with every name taken from the config. It runs `run_cluster.py <config> launch` with `MA_LAUNCH_INVOCATION` set to its own token. Exit 0, 3, 4 or 5 means something was submitted: nothing is stopped, and on 5 (or 3 with no keeper recorded) it says the keeper must be started by hand. Exit 1 or any other code stops clusters only when `clusters.json` carries this token with status `failed`, and then exactly the ids it names, by id; the old script stopped everything on any non-zero exit. When every run is done, or the run cluster has stopped itself, it runs `collect` and confirms that every label is collected locally for this launch (`result.json` with the launch id of this invocation's assignments) before it stops anything. The old script shut down first, while `status` could print `stored=None` with the agent VM holding the only copy; unconfirmed now means exit 4 with the run cluster left up. Further guards: a credit cap (`--cap`, default 650: billed credits of the recorded ids plus a projection for live instances; at the cap one collect, then a stop by id, exit 3); a stray sweep (a live cluster with this launch's names, unrecorded, created after the launch, stopped by id on its second sighting); a refusal (exit 7) of configs without `run_timeout_hours` or `cluster_timeout` unless `--allow-no-cloud-limits`; network errors retried and never read as "not running"; a `relaunch` of a run still missing after `--start-minutes` (exit 2 if it still does not start). Exit codes 0-8 are in the module doc. Self-tests LW1-LW8 (36 cases at first, fakes for the runner, the Coiled listing, billing and the clock) were written first and failed against a stub. Codex round 1: `collect --no-shutdown` (new in `run_cluster.py`, CN1-CN2) so stopping stays the watch's, by verified id; a stray is stopped only when this invocation's construction journal records creating its id (others are reported); the projection uses Coiled's live instance count per cluster, else the configured maxima; the emergency collect at the cap is one attempt bounded at 10 minutes, and the cap and `--max-hours` are checked between collect retries; a relaunch counts only when it exits 0 or 4 (at most 3 attempts); the launch has a 45-minute deadline past which it is reaped and treated as exit 4; and exits 2, 4 and 6 log every live cluster of the launch's names with its ownership (LW9-LW14). Codex round 2: the watch never runs `keeper` (its reconcile stops live helpers absent from this launch's record), it only says to start one by hand; `worker_side.verify_attached` shuts down a mismatched cluster only when that attach created it (the construction's 120 s ownership rule) and otherwise refuses and leaves it alone; `launch` still replaces same-named helpers it finds live (`_fresh()`, known and unchanged), so the watch refuses to launch (exit 8) while any cluster of the config's names is live or the listing cannot be read; each collect is one attempt with a 30-minute deadline, at most 6; and exit 1 also logs the leftovers (LW15-LW17, RC18-RC18f).

## Status
