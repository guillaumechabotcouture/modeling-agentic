## Changelog

**Concurrent appends, test-only engine references, a per-test CI watchdog and a load-proof P45D-4 (follow-up to #133).** Each fix has a test that failed first (α). (1) `scripts/lib/safe_io.py`: when several processes create the same new file through a directory fd at the same moment, `openat(O_CREAT)` can return ENOENT. This was seen on macOS: 130 `LinkRefused` errors in 4,800 appends. Atomic publishes and opens of existing files were not affected. `write_nofollow` (append, exclusive and plain writes) and `open_append_nofollow` (and so `append_text`) now open through `_openat_create`, which repeats the same single `openat` with `O_CREAT|O_NOFOLLOW`. There is no check-then-open. It retries only ENOENT, only while the directory still exists, and at most 100 times. Link and hard-link refusals are unchanged. New cases: SI-AR (4 spawned processes x 400 appends to new files through all three entry points; every line present once and no exception) and SI-AR2 (appends through a link, a linked directory or a hard link are refused). (2) Codex P1 on #133: `toolkit/import_guard.py` no longer reads `MA_IMPORT_GUARD_TEST_REFS`, and `toolkit/spec/toy_engines.py` no longer reads `MA_TOY_SPEC_LOG_DIR`. Code in a self-test registers the toy engines in-process (`allow_test_refs`, or `toy_engines.enable_for_test(log_root)`). Worker processes receive the registration only as their pool initializer's argument: `import_guard.pool_kwargs()` / `init_worker`, wired into `compute.py`'s local pool (`_local_init`) and the benchmark runner's pools. The toy call log is rooted in a temporary directory the self-test creates outside the run dir. New cases: IG5 (a process with the variable set refuses the toys, and its pools get no initializer), IG6 (a worker allows a test reference only with the initializer) and EP42 (`toolkit/analysis/run.py` with both former variables set refuses the toy engine and writes no call log; before the fix it ran and wrote 16 logs). (3) `scripts/self_tests.py --per-test-timeout S` (default 900; 0 means no limit) runs each self-test in its own session. One that runs longer is killed with its process group, named (`TIMED OUT: <path>`) and counted as failed, while the others continue. Each group title shows the test's duration. CI passes `--per-test-timeout 900`. New case: ST13. (4) `scripts/compute.py` P45D-4 no longer compares wall time with 0.6 x serial, which failed at 7.35 s against 7.2 s under CI's `--jobs 2`. It now checks the peak number of tasks running at once, taken from the tasks' own start and end times. With one process per worker, overlapping tasks ran on different workers. Wall time is reported for information only.
