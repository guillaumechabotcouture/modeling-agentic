## Changelog

**Base outcome adjustments (F6 run 4, owner decision R3; principle 4).** In F6 run 3 the engine's PBO nets have about the same effect as pyrethroid-only nets at moderate resistance, and its dual-AI nets a weaker effect than their trials. The owner decided that the base case uses the trial relative effects, and that the engine's own effects become the stress test. The new optional field `analysis.outcome_adjustments: [{id, component, reference, value, source}]` (`toolkit/analysis/outcome_adjust.py`) is applied in `core.Analysis.evaluate`, so it reaches every evaluation: point, draws, stability, sensitivity, decision tests, plan variants, and the boundary check's engine side. Each package holding `component` (and not `reference`) has every reported outcome and window burden set to `value` times that of its counterpart, the same package with `reference` in the component's place. Costs are left as computed. A model correction on a counterpart is copied onto the derived package (`derived_from`), so the guard sees it. Only outputs change, not engine parameters, jobs or rows, so stored engine rows are reused. The boundary check now runs each adjusted package's counterpart on the engine. An `outcome_ratio` decision test accepts the value `"engine"` to remove its component's base adjustment and re-evaluate (the engine's own effect); its record gives the benefit per value (`check_by_value`) and the base adjustments in force. `point.yaml` records the adjustments. Sign-off refuses: unknown or identical components, a ratio that is not positive, no source, a reference that is itself adjusted, a component adjusted twice, a component the comparator holds, a component with no counterpart, and `"engine"` without a base adjustment. Self-tests SP-OA1-11 (schema) and OA-R1-6 (`run.py`, joint toy) were written first and failed (SP-OA9 already passed, because the schema accepted unknown analysis keys). The module has its own self-test (OA1-4). Codex round 1 raised seven P1s and two P2s. All are fixed, each with a test written first that failed (β).
- An outcome_ratio value `"engine"` takes the whole re-evaluation (P1-1).
- Sign-off refuses: a package holding the component that has no counterpart (P1-2); a package holding two adjusted components (P1-3); an outcome_ratio test on a base adjustment's reference, or on an adjusted component against another reference (P1-4); a validation.burden or anchor arm holding an adjusted component, whose window and age-band outputs the adjustment cannot reach (P1-5, P1-6); and a likelihood or posterior calibration, which fits raw outcomes (P1-7).
- Every `y` entry, DALY parts included, and the grouped outputs follow the counterpart (P2-8).
- A ratio of 1 on an adjusted component is a real case (P2-9).
- Tests: OA5-9, SP-OA12-13. Codex round 2 raised two P1s, both fixed with their tests written first (γ):
- With base adjustments, an outcome_ratio test may vary only a base adjustment, an adjusted component against its base reference (`outcome_adjust.dt_problems`, used by sign-off and the run; OA10).
- Numeric cases are guarded with the point evaluation's corrections (OA-R7).
