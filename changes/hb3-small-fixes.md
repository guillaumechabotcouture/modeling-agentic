## Changelog

**Harness baseline hb3, fixes 4 and 6: the expected-value plan, unrun decision tests and the harness-gap key.** (1) `toolkit/spec/spec_critique.py` gains the pre-sign check `expected_value_plan` (principle 1). `expected_objective` reads the spec's question for an objective stated in expectation: an optimising verb, at most three words, then "expected" and a quantity (not "expected to" or "expected in"), or "in expectation". It names no disease, outcome or unit. When the question asks this and `deliverable.plan` is not `expected_value`, the sign-off sheet shows a MEDIUM, declarable through `principle_departures`. When the plan is set, the sheet shows an INFO row. Either row records the detected wording (`detected`). The draft_spec prompt (`agents/v2_sdk_tasks.py`) and the decision-spec skill tell the drafter to set the plan, or to declare the check with its reason when the spec cannot carry the plan (for example `by_group`). (2) `toolkit/analysis/contract.py` `decision_test_not_run_findings` adds one `decision_test_not_run` finding (HIGH, declarable, remedy "Owner amendment: ...") for each decision test that the spec declares and that ended `not_run`. The finding quotes the harness's reason. `toolkit/analysis/api.py` `gate_findings` adds these findings after the plan-changing ones. Automatic tests the spec does not declare are left out. An unreadable spec reports every test that did not run (fail closed). (3) `agents/findings_ledger.py` `harness_gap_key` is now the finding's answer fingerprint (id, kind and remedy class), as owner answers have been since #357. It no longer includes the remedy as written, so a critic's rewording keeps the gap. A gap recorded under the earlier key still holds on a resumed run (`legacy_harness_gap_key`). A provisionally accepted unrun test reads "plan changes: not tested" in the report, and an answered one is fixed once a gate no longer reports it. Self-tests: SC43-SC47, K-DTP8, AP9b, L19b, L20 (revised), L20b, SD3, T_NOT_RUN_PROVISIONAL.
