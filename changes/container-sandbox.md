## Changelog

**A kernel-enforced derivation sandbox for unprivileged containers (`landlock-seccomp`).** Inside an unprivileged Docker container, which is how the outside benchmark runs the harness, bubblewrap cannot create namespaces, so every derivation failed closed (`derivation_unsandboxed`). When no bubblewrap kind passes its probe, `scripts/pipeline.py sandbox_kind()` now probes `landlock-seccomp`. It is used only with filesystem or cgroup evidence of a container; the `container` variable and operator settings never count (owner, 2026-11-23: containers only, bubblewrap stays required on hosts). The launcher sets the caps, then confines itself before the script runs, with `scripts/lib/kernel_sandbox.py` (#383). It sets no_new_privs. A Landlock ruleset (ABI 3 or later), allows reads only of the work directory, Python's library directories, the system library directories and five `/etc` files, and writes only of regular files and directories in the outputs' directories. A hand-built seccomp-bpf filter for x86_64 and aarch64 refuses sockets, process creation, exec, ptrace, setting limits, mount and namespace calls, io_uring, and signals to other processes. Both hold for the whole process, native code and second interpreters included. A probe must meet every refusal, and without seccomp or Landlock derivations fail closed. This replaces a first design enforced by a Python audit hook, in which Codex round 3 found 10 escapes. The record holds the kind, the container evidence, the Landlock ABI and the container's network. Every report has a "Derivation sandbox" block, with a one-sentence limit for the fallback. The library itself is #383, merged first. Self-tests: DI-K0 to DI-K11 (`scripts/pipeline.py`, including the round-3 escape reproductions) and T13s (`agents/stage_machine.py`). Design and guarantees table: `docs/design/v2-derived-inputs.md` §7.
