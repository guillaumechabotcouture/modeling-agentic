## Changelog

**v2 autonomy 1F: the owner lifecycle is wired (`OWNER_LIFECYCLE_WIRED = True`), and under `--signoff lead` every owner decision gets a provisional lead answer (owner default D2).** Items F.1, F.3, F.5, F.6 and F.7 of `docs/design/v2-autonomy-brief.md` PR 1F, as re-audited (F.2 and F.4 were fixed by #258). A decision test that changes the plan (`decision_test_changes_plan`) was made non-declarable, so a run that met one at the last round ended not accepted or `run_failed`. Now `apply_owner_rule` marks it for the owner with a fingerprinted item (`_bearing_item`: the finding, its claim and the analysis's record of the test), the validator turns the would-be DECLARE_SCOPE into AWAIT_OWNER, and the GATE writes the request (`_request_scope`: `scope_signoff.record`, fingerprints kept in `run_state.json` as `_request_owner` does for amendments). Under `--signoff owner` the run pauses at OWNER_DECISION (`paused:awaiting_scope_signoff`) until the owner answers with `scripts/scope_signoff.py sign`; the harness records the answers and the next gate applies them: an accept makes the finding declarable (`owner_signed`), a decline holds the gate (`scope_declaration_declined`). Under `--signoff lead` the run never waits: `h_OWNER_DECISION` writes the lead's provisional `accept` for each unanswered item (`scope_signoff.provisional_answers`, `provisional: true`, `plan_changing` when a decision test changes the plan), records it like any answer, and goes on; this covers the owner-amendment requests too (the ledger counts a lead's recorded answer only in a lead run: `findings_ledger.owner_answers(..., lead_ok)`). `report.md` lists every provisional decision after the draft (owner items and, from `engine_choice.json`, engine departures credited `provisional_lead`), and those whose decision test changes the plan head the report above the draft. The owner later confirms or overturns each (`scripts/scope_signoff.py review <run_dir> --finding <id> --confirm|--overturn`; `provisional` lists them); the lead's answer stays in the record beside the review, and an owner's later sign-off keeps the reviews. Under `--signoff none` a decision-bearing finding stays non-declarable, as before. Answers count by the run's mode, which v2 now passes (`v2_gate(..., signoff=)`, `scope_signoff.gate_findings(..., mode=)`), not `MA_SIGNOFF_MODE`. Codex round 1 (γ): `harness_record` writes the trace nonce before the ledger and re-records an entry whose nonce the trace lacks, so an interrupted record cannot leave an answer the gate never verifies; `provisional_answers` refuses an unreadable `scope_signoff.json` (the lead run ends `run_failed` instead of overwriting an owner answer); a lead's answer counts only when the harness made it provisionally; `review` marks only the latest answer for a finding. Codex round 2 (δ): an owner's recorded decline of a Phase 49 policy finding holds the gate even without a decision-bearing finding beside it (nothing new is put to the owner there); in v2 a lead's answer to a policy item also counts only when provisional; `provisional_answers` keeps an owner answer that arrived since it read the record; `provisional` raises on an unreadable record, so the report says the list could not be read. Known limits, for follow-ups: the default toolkit backend records plan-changing decision tests in `analysis/decision_tests.yaml` but emits no `decision_test_changes_plan` finding, so this lifecycle is exercised by the spike backend's finding today (the toolkit path is the conflict rule, W0-F); a decision-bearing finding before the last round still goes to the fix loop, which cannot fix it; an owner run whose request file is lost after the pause waits; under `--signoff lead` an amendment accepted provisionally whose critic still reports a STRUCTURAL PLAN mismatch goes to SPEC and pauses `awaiting_spec_amendment` (step S7, unchanged); a decision-test item shows the owner its claim, not the test's numbers.
