## Changelog

**Dispatch code in `scripts/compute.py` is not part of the batch-reuse fingerprint (owner, 2026-11-12).** PR #204 changed only how chunks are placed, retried and shown to the autoscaler. Yet it changed `code_fingerprint` for every stored batch: on the P6 preview's snapshot all five finished calibration batches hashed `4d089cdf7112` on the old base and `2e84f6b5e8d6` with #204, so a run on it would have recomputed about $200 of finished work. Only ok rows are reused, and a chunk's rows come from `_remote_task` and `_call`, so the placement, retry, scheduler-plugin and ledger code cannot change a reused row. `FP_DISPATCH_EXEMPT` names those top-level definitions (`_sched_view`, the demand marker, BusyWorkerGuard, ComputeTagPlugin, the retry and adaptive constants, the ledger, progress and heartbeat functions). `_fp_compute_source` hashes compute.py with each of them, and the comment lines before it, replaced by a placeholder. Everything else in the file stays hashed: the model call path, `_remote_task`, the bundle, the worker environment, the breaker, `map_fn`, the fingerprint code and its constants, and every comment outside an exempt definition. A listed name that is not found stays hashed (FPX1 checks they all exist), and a file that does not parse is hashed whole. This change itself moves the fingerprint once: P6 and F6 stay on base 15b8b0d, and the exemption helps from the next run. After the Codex review (round 1): `_rows_done` is hashed (it handles rows on their way to the reusable journal), an assignment is exempt only when every name it sets is exempt and no other statement shares its lines, and the lines before an exempt definition are replaced only when they are blank or comments. Self-tests FPX1-FPX5 (`scripts/compute.py`), written first, failed before the change (`FP_DISPATCH_EXEMPT` undefined); FPX6-FPX7 (written first, failed before the round 1 fix) and a revised FPX5 (an existing file edited). Codex round 2 (P1): `_map_dask` itself decides which params an index stands for and which returned rows reach the reusable journal (a reversed input enumeration swapped results between keys with the fingerprint unchanged), so it stays hashed (FPX8, written first, failed before). That narrows the benefit: a change inside `_map_dask`, as most of #204 was, still changes the fingerprint; only the top-level helpers, plugins, retry constants and ledger code are exempt. Follow-up: extract `_map_dask`'s scheduling-only parts (lost-chunk handling, demand markers) into exempt top-level functions. No cloud run.
