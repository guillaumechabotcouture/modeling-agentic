## Changelog

**Critique checklist: five structural checks the domain and red-team critics answer.** Owner decision 2026-11-23, from an outside benchmark in which frontier agents' models stopped at "good": comparator asymmetry, holdout windows over shock periods, burn-in drift, rankings driven by under-reporting, and reduced-form natural history that sidesteps a known tension. They are principles 8-12 of `.claude/orchestration/decision_design_principles.md`. New `toolkit/spec/critique_checklist.py` holds the items and the schema. The domain and red-team critique files carry `checklist: {item: {answer: pass | finding | not_applicable, reason, blockers}}` for all five items, every round. `validate_critique(..., checklist=True)`, called so by `v2_gate` in any run (its run_state.json or spec exists; not on a replay of stored gates), refuses a missing or unknown item, an unknown answer, a blank reason (not_applicable included), and a finding that names no open blocker of the file, as schema errors. A finding is an existing blocker, so the checklist adds no finding, and pass or not_applicable costs no round. The schema errors never quote critic-written text (they reach the repair task's system prompt): they name it by a marker (`[CK-K<n>]`, `[CK-A-<item>]`, `[CK-B-<item>-<n>]`), and the repair's review message carries the marked text as JSON data (`critique_checklist.repair_data`, read with no link followed). The critique prompt lists the items; `StubTasks` answers them; the harness id stamp renames the checklist's blocker references; the gate record holds `critique_checklist`. Harness-computed audits of comparator symmetry and holdout-shock overlap are deferred to the self-audit build (#369). Self-tests CL1-CL16, CK1-CK6, SCK1-SCK3, SM-CK1-SM-CK5.
