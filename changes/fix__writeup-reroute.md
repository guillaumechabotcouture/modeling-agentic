## Changelog

**No critique round with nothing to fix: write-up re-review route, owner-held findings declared (harness baseline hb1, fixes 6 and 7).** Two causes cost rounds in 6 of the 10 hb1 runs. (G) A write-up-only fix went FIX_LOOP -> WRITE with the round raised, and the domain and red-team critiques stayed on the round before, so the post-write gate refused them as a schema error ("round must be N, got N-1") and re-ran them through the schema repair, using up a `MAX_SCHEMA_REPAIRS` try (dengue R1 and R2, measles R1, tb R2). FIX_LOOP now records the revised round (`run_state.json` `tries.rereview`); after the revised draft's presentation review (or straight after WRITE for a not-accepted draft) the machine goes to CRITIQUE, which runs the domain and red-team critics at that round as a re-review of the draft, then GATE. The schema counter is not touched. New edges PRESENTATION -> CRITIQUE and WRITE -> CRITIQUE. (H) The medium rule (4m) sent a tested MEDIUM finding to the fix loop although the lead had accepted it provisionally (its remedy is an owner amendment), the fix loop had no task for it, and two more critique rounds ran before the run declared it (malaria R2; measles R2 round 2 the same for three findings). `apply_medium_rule` takes `owner_held` (new `owner_held(ledger)`: accepted by the owner or the lead, or awaiting the owner's answer on an amendment) and never counts those as work for the fix loop: they are declared (3m), and the rationale says the owner's answer decides them. h_GATE syncs the findings ledger once, before the medium rule, and uses that ledger for the owner's declines too. Pre-write, a fix loop with no task where no open finding the gate holds could be fixed by a task (only write-up or owner-held findings) goes to WRITE in the same round (mode declared when the owner holds a finding, else accepted) instead of another critique round. The hb1 re-requests of the owner were not the same fingerprint: the critics reworded the claim in each extra round, so the fingerprint changed. With the extra rounds removed, the same answered finding is asked once. Self-tests WR1-WR3, WR1b, WR4, WR6, WR7, WR7b and WR8 failed before the fix. WR5 (asked once) already passed: same-fingerprint answers were already honoured.
