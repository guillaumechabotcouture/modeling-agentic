## Changelog

**No critique round with nothing to fix: write-up re-review route, owner-held findings declared (harness baseline hb1, fixes 6 and 7).** Two causes cost rounds in 6 of the 10 hb1 runs. (G) A write-up-only fix went FIX_LOOP -> WRITE with the round raised, and the domain and red-team critiques stayed on the round before, so the post-write gate refused them as a schema error ("round must be N, got N-1") and re-ran them through the schema repair, using up a `MAX_SCHEMA_REPAIRS` try (dengue R1 and R2, measles R1, tb R2). FIX_LOOP now records the revised round (`run_state.json` `tries.rereview`); after the revised draft's presentation review (a revised not-accepted draft, which otherwise goes WRITE -> GATE, gets one too) the machine goes to CRITIQUE, which runs the domain and red-team critics at that round as a re-review of the draft, then GATE. The schema counter is not touched. New edge PRESENTATION -> CRITIQUE. (H) The medium rule (4m) sent a tested MEDIUM finding to the fix loop although the lead had accepted it provisionally (its remedy is an owner amendment), the fix loop had no task for it, and two more critique rounds ran before the run declared it (malaria R2; measles R2 round 2 the same for three findings). `apply_medium_rule` takes `owner_held` (new `owner_held(ledger)`: findings the owner, or the lead provisionally, accepted; one still awaiting the answer goes to OWNER_DECISION first, so nothing is declared before the owner answers) and never counts those as work for the fix loop: they are declared (3m), and the rationale says the owner's answer decides them. h_GATE syncs the findings ledger once, before the medium rule, and uses that ledger for the owner's declines too. Pre-write (no manuscript or report), a fix loop with no task after a 4m gate with no unresolved HIGH, whose tested findings are all the write-up's or owner-accepted, and with no open blocking finding a task could fix, goes to WRITE in the same round (mode declared when the owner holds a finding, else accepted) instead of another critique round. The hb1 re-requests of the owner were not the same fingerprint: the critics reworded the claim in each extra round, so the fingerprint changed. With the extra rounds removed, the same answered finding is asked once. Self-tests WR1-WR3, WR1b, WR4, WR6, WR7, WR7b, WR7c and WR8 (WRITE case) failed before the fix; the WR8 CRITIQUE cases (a fixable finding, a report-only draft, an unresolved HIGH, another rule, no gate file) pin the shortcut's limits (Codex r1). WR5 (asked once) already passed: same-fingerprint answers were already honoured.
