## Changelog

**Review workbench: page, Overview, Steps and Fit views.** `python3 tools/workbench/workbench.py --roots <dirs>` serves a read-only page on 127.0.0.1 (loopback Host only, no outbound call, reads through `lib.safe_io.read_nofollow` confined to the run directory, no engine or harness loader imported; under `tools/`, so outside `compute.code_fingerprint`). A view is a module that returns checks, facts, tables, chart declarations and notes; the page renders any view with no view-specific code (five chart kinds as inline SVG). **Steps:** eight checks on the deterministic chain (how the run ended, pipeline and launch commit, spec on disk against the signed spec, each analysis file's recorded input hashes against the files, manifest, loops and failed tasks, model spend by stage) and a graph of harness-written files and their inputs. **Fit:** one generic model (targets, parameters, change between rounds, blocks, offsets, sensitivity, series) filled by an adapter per calibration method (`history_matching`, `posterior`), with eleven checks written once on the generic model; a flagged item covered by a signed declaration whose decision test ran is "look", otherwise "problem"; thresholds come from the method's own file and the workbench's own are labelled. **Overview:** every view's checks in reading order. A glossary of scorecard, goal and gap codes is parsed from the specification. `--accept <run> <file>` compares the page's data with acceptance values re-derived from stored runs; the acceptance files hold run values and stay beside the runs, outside the repository (Steps 14 of 14 and Fit 298 of 298 entries on one stored run; Fit 169 of 169 and 78 of 78 on two runs of other disease areas and methods). `leak_check.py` fails a push if a committed number also appears in a named run. A fresh agent given only three pages (two fixture runs with one planted defect each and a clean one) named both defects and their evidence. Self-tests in every module. Stacked on the fixtures.
