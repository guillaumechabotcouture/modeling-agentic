## Changelog

**W0-H1: `amend`, one path from a finished or blocked v2 run to a re-signable child run.** `python3 -m toolkit.spec.amend <parent_run> --patch <amendment.yaml> [--from-request] [--out DIR] [--signoff owner|lead]` (`toolkit/spec/amend.py`, new) never writes the parent. It makes a child directory beside it (`<parent>.amend<k>`), built in a `.partial` directory and renamed into place only once the patch applies and the amended spec validates. The child holds: `metadata.json` with `parent_run` ({run_dir, run_state_sha256}, the form #311 records from `MA_PARENT_RUN`), `parent_spec_sha256` and `code_pin`; the parent's inputs and stored engine batches, copied through `lib.safe_io` with their modification times, and a link anywhere in the parent refuses the amendment; never the parent's run state, sign-off records, sheet, findings, critiques, report, figures, engine choice or typed analysis outputs; `run_state.json` at SIGN, paused awaiting_signoff, with the parent's question, rounds, budget and sign-off mode. Patch: `id`, `reason` (required), `spec` and `dossier` lists of `set` / `add` / `remove` operations by dotted path, with a list element by index or `[key=value]` (exactly one match). A path that does not resolve, an operation on the wrong kind of node, a patch that changes nothing, a parent neither final nor paused, or a spec that no longer validates is refused, and no child is made. `--from-request` reads the parent's `spec_rethink_request.json`. It must name the parent's signed spec. Its briefs and findings become the amendment's why, and its `patch` is applied when present (else `--patch` is required). Then: the spec critique's counts; review conditions imported (W0-G, `review_conditions.py import --critique --parent`); the sign-off sheet regenerated; a scratch copy signed as the child's signer with the sha256 values that will be shown (the dry-sign); and the reuse report. The reuse report gives each stored batch's rows reusable and rows to compute, the rule that decides and why. Job-keyed batches (the joint calibration's calls, `toolkit/analysis/row_reuse.py` batches) count rows with the current engine identity and adapter digest. Other batches use `compute.reuse_report`'s code fingerprint. `amendment_record.json` holds the changes by path (before and after), the checks, the code pin and three commands: the owner sign command with the spec, sheet and derivation sha256 in full, the launch (`main.py --v2 --resume <child>`), and `smoke_check.py` with markers. The CLI exits 1 when the dry-sign fails, and then prints no sign command. `scripts/lib/pipeline_id.py` gains `code_pin(repo)`: the commit, whether the tracked files are clean, and the remote branches that contain it. Codex review round 1 (γ) found 20 P1s; fixed here: a child inside the parent is refused; the run state is written last, so a child that stopped part way cannot be resumed; the parent spec must be the signed one; file and directory modes are kept; an unreadable parent directory refuses; the checks the SPEC stage runs before SIGN (backend pre-sign checks, geometry) run on the child, and its sheet shows the backend candidates; a failed review-condition import, or a geometry exception waiting for the owner under lead, fails the dry-sign; a parent run under `--signoff none` gives an owner-signed child; launch values are typed and quoted; parent dispositions (`done_when_registry.json`, `scope_declaration.yaml`, `fix_progress_*`, `models/decision_tests/`) are not copied; job-keyed rows are counted once per job, an untrusted joint-calibration file counts nothing, and files the runtime trusts by a reuse sidecar are listed; a `[key=value]` selector needs the key, a number path that names both a number key and a text key is refused, YAML aliases are refused, and the id is a short token; `code_pin` reports `clean` from git only. Left as known limits: rows listed reusable are matched to jobs only when the run builds them (the report says eligible, not promised); a decision-brief child can still have `success_criteria.yaml` edited after the dry-sign (the existing signer binds the three hashes it is given). Not in this PR: the S7 routing in `agents/stage_machine.py` (#316 handles the lead path; `amend` is the command it can call); a cost for the rows to compute; carrying comments inside the spec, since PyYAML keeps only the leading comment block and the record's changes say what moved.
