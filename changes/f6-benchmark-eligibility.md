## Changelog

**Engine eligibility requires the engine's trial benchmarks for the components the spec uses to be in band (owner
decision 2026-11-12).** Each engine with benchmarks keeps `benchmark_coverage.yaml` beside its module (malaria,
compartmental, renewal), saying which component values and which estimand (effect against none, against another
component, durability, interaction, cost per outcome) each benchmark covers, or why it covers none, and which
components no benchmark covers. `agents/analysis_backend.py` `eligible_engines` refuses an engine when a covering
benchmark is `out_of_band`, `not_assessable` or `band_mis_based` (each named in `why_not`) in the verified benchmark
record of the engine version in use (`toolkit/engines/benchmark.py` `verified_results`, its version equal to the
card's); a record from another engine identity counts for nothing. A spec-level `engine_departures` entry (engine,
benchmark or component, reason, decision test) makes the engine eligible only once the
owner has signed the spec (the pre-sign check counts it as proposed, including for a spec that names its engine);
it is validated by the schema, shown on the sign-off sheet, recorded in `engine_choice.json` and declared in
`results.md`. Both benchmark roles gate: a held-out benchmark stands as validation (never a fitting target) and a
fit target out of band means the fit failed; each failing benchmark's role is recorded in `why_not`,
`benchmarks_not_in_band` and the departure. Owner decisions 2026-11-13 and review round 1: a cost-per-outcome benchmark gates only when the spec charges the component through the engine cost output it prices (otherwise it is reported); a used component no benchmark covers blocks unless a departure names a decision test on its effect; a departure counts only with the owner's signature (a lead cannot sign a spec that needs one), and only when its decision test varies the related effect; the check also runs when the spec is signed and when the analysis validates it; coverage must be for the engine assessed and match its pack and record; duplicate record ids are refused; interactions apply only when a package can hold every component; the configuration assessed is the one the run uses. Review round 2: `toolkit/spec/preconditions.py` (`problems(run_dir, spec_bytes, signer)`, a registry every signing path and the validation before a run call, and `decision_test_runs`, which says whether a departure's test runs on the run's path and changes the effect); the coverage is bound to the pack declarations the record was scored against (band digest); cost drivers gate wherever they are charged; effect parameters are checked against the engine version (malaria B7/B8: use_rate, and net_kill_shift from v0.17). Review round 3: one source of truth for what a decision test applies: `toolkit/analysis/decision_tests.py` `plan_test(spec, test, evidence)` (resolved values, arm evidence at the spec values or the verified results, reachable targets, modified and subtraction packages), which run_one executes and the precondition reads (with `prerun_evidence`, the batch's own `design_box`); coverage and pack are resolved from the engine class's module (aliases behave like the canonical reference) and the engine's effective results path; the effective package set (Spec.packages()) everywhere; the shared signing check validates departure shape and, for engine: auto, every candidate. Review round 4: before the run, inputs only (a parameter test's values span the declared range or a stated `range_fraction`; an interaction test targets the departed benchmark's own component pair); during the run, outcomes (`check_departures`: run, non-identity at the calibrated point, no targeted package skipped, a realised benefit change; else the non-declarable, decision-bearing finding `departure_test_ineffective`); every decision-test record carries `benefit_change` and `missing_subtraction`; signoff.sign and pending validation run the shared check for engine: auto. Self-tests G1-G30 (analysis_backend), BC1-BC10, PC1-PC10 (preconditions: PC5 the input table, PC6-PC10 a real calibrated Analysis), T17p (stage_machine) (`toolkit/engines/benchmark_coverage.py`).
