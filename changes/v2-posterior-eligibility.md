## Changelog

**Engine eligibility for a declared posterior's training benchmarks takes its status from the fit's verified chosen point.** Owner decision, 19 Nov. With `uncertainty.net_effect_posterior` declared, the run evaluates every posterior column at the fit's chosen point (v2-posterior-point). The benchmark precondition still read each benchmark's status from the engine's `results.yaml`, which is scored at card defaults, so a training target could block an engine at a point the run never uses. Now `benchmark_coverage.posterior_trained` loads the posterior through the run's own path (`uncertainty.net_effect_sample`). `load_posterior` returns `trained`: the file's `plan.targets_train` that its `finalize()` replay checked the chosen point in band on. `gate` treats those benchmarks as in band, with `status_source: posterior_chosen_point`. Every other benchmark, held out of the fit, still takes its status from the record, still blocks when it is not `in_band`, and still accepts an owner-signed `engine_departures` entry. The eligibility output (`gate`, `assess` and the engine-choice rows' `benchmark_status_source`) records the status source per benchmark. A declared posterior that does not load makes the engine not eligible (fail closed). Specs without the field are unchanged. These tests were written first and failed before the change: BC11 to BC15 in `benchmark_coverage.py` (α-β). Codex's read-only review raised three P1s and two P2s. The three P1s and one P2 were fixed, with their cases written first and failing (γ-δ). First, `trained` maps each id to the digest of the pack declaration the replay verified (`band_digest`), and a benchmark counts as trained only when its record row is bound to the same declaration (BC11b). Second, an id the file also lists in `plan.held_out_untouched` is not trained (BC14). Third, a declared posterior is loaded before the toy-engine exemption, so a toy engine with a posterior that does not load is not eligible either; this also tests the wiring through `assess` (BC16). The other P2 is not changed: a report-only cost benchmark keeps the record's status and the label `results.yaml`, which does not affect eligibility. Against the real record, every fit target's record digest equals the declaration digest the replay uses, so no row is dropped by the new binding. Codex round 2 raised one P1 and one P2. The P1 is fixed, with its case written first and failing (BC17; ε-ζ). The digest was computed when the file was loaded, so a declaration changed after the fit (same id and band, other arms) would have passed on old seed evidence. `net_effect_fit.run` now writes `target_digests` (`target_digests()`, the fit targets' declaration digests in the pack it ran with). `load_posterior` trains a target only when that recorded digest equals the current declaration's. A fit file without `target_digests` trains nothing, so every benchmark gates on the record, and a fit must be re-run on this code for its targets to count. The P2 is not changed: a passing `assess` call through a non-toy engine is not exercised by a self-test, because it needs an engine's verified record. Codex round 3, the last, raised one P1 and two P2s, all fixed with their cases written first and failing (η-θ). The P1: `run()` hashed the pack file rather than the pack it evaluated. It now hashes the effective pack, which a normal fit shares with the pack file (BC19, a static and invariant check, since `run()` needs engine runs). The P2s: a malformed `uncertainty` section no longer raises in `posterior_trained` (BC18). BC16 now fails if `assess` raises, and BC14 now uses a real benchmark the replay does not check, with a matching digest.
