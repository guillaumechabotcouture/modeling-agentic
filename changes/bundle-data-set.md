## Changelog

**`make_bundle` ships the declared data set to dask workers.** The reuse key's `data_set` part hashes the files `FP_DATA_SET` names (repo `data/`, `.claude/orchestration/`, and the non-Python files of `scripts/` and `toolkit/`, #314), but the bundle shipped only the run's `models/` and `data/` and the repo's `scripts/` and `toolkit/`, so a worker that read repo `data/` or `.claude/orchestration/` computed without them while the key named the launcher's copies; a data-set file over the bundle's size cap was also left out. `_data_set_files` now lists the data set once: `_files_digest` hashes that list and `make_bundle` ships exactly it, whatever a file's size. The bundle record reports `data_set_files`. Codex round 1: the data set leaves out any `_truth*` path component, also where a link leads (eval_paths' hidden-material rule; the walk had left out only directories named exactly `_truth`, a no-op change for a tree without such paths), and the bundle's other walks leave out `_truth*` directories; a dangling link in the data set is recorded in `data_set_unreadable` instead of stopping the batch. Self-tests BD0-BD5, with an explicit expected manifest. Known limits, unchanged by this PR and shared with the `scripts/` and `toolkit/` members the bundle already shipped: a worker caches its staged bundle per run directory while repo members are shared paths, so two runs from one repo path at different repo states on one worker can see each other's repo files; the key and the bundle enumerate the live tree at two moments; staging does not replace a directory with a file.
