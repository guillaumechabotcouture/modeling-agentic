## Changelog

**Run console: run dossier (Spec, Evidence, Engine and Calibration tabs).** The owner said the console "doesn't show the spec, or the evidence, or the engine details". Four read-only views beside Stream and Figures now show what a run is made of. **Spec:** the signed `decision_spec.yaml` as tables (units and their count, engine attribute bindings, defaults accepted, components, cost items with the base-year value and the per-person cost over the window following `toolkit/alloc/costs.py`, objective, constraints, comparator, calibration, uncertainty, decision tests with units), and the sign-off history (current and `evidence_planner/superseded_signoff_*`), each archived sign-off diffed field by field against the next one. **Evidence:** `evidence/registry.yaml` (a stub says so), staged parameter registries with where the spec names each entry, `citations_*.txt`, staged inputs with their recorded and current hashes, derivations as input → script → output columns with used and ignored columns and reasons, and `data/input_checks.json`. **Engine:** candidates and why each was ineligible, the card (mechanisms, components, unit attributes with ranges and bindings, outputs), parameters (prior range, fit box), benchmarks with out-of-band rows flagged, the re-stamp record (proof vs recomputed, `validate_once` pending or done), and the engine identity. **Calibration:** settings, clamped units, identifiability, per-region targets and calibrated values, emulator held-out accuracy. `tools/run_console/dossier.py` builds it through the console's confined reader (no link followed, no path outside the run dir, no harness loader, no engine import); the one outside read is the checkout's own benchmark results file, only when its sha256 equals the run's record. `GET /api/dossier`, `tools/run_console/dossier.js` under the page's CSP. Tests first: DS1-DS5 (data model on a toy run with every artifact, fail closed, a traced no-reads-outside check, escaping of hostile strings through node, the endpoint and the glossary). `scripts/write_audit.py` scans the new module. Review round 1 (Codex, DR1-DR9): the calibration is joined only to the inputs it was computed from (spec and input hashes), and rendered by its method (likelihood and posterior: convergence, bound hits, Pearson residuals, observed vs expected; an unknown method is not supported; a failure needs the owner); a payload without its required fields is not available, never zeros; per_reached costs per person reached; an archived spec hashed and parsed from one read; the re-stamp chain (computed by, re-stamped to); equation benchmarks keep reference, tolerance and errors; small values in scientific notation; removed group rules and envelope tests (USD) described. Round 2 (DR10-DR12): the joined units table is parsed from the bytes that were hashed, the freshness checks run for every method, tolerances keep their significant digits, and removed group rules are found in the raw list shape.
