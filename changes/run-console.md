## Changelog

**The run console: a local page for the owner of a v2 run.** Design: `docs/design/v2-run-console.md`. `scripts/run_console.py` (stdlib `http.server` on 127.0.0.1 only, a per-process token on every POST, a Host check) serves `scripts/run_console.html` (vanilla JS, a small local markdown renderer, no CDN). The main pane is one chronological stream rebuilt from the run's artifacts: stage changes with why and spend (`run_state.json` through `stage_machine.load_state`), engine-batch progress with an ETA (`models/compute_ledger.json` reservations joined with `.compute_progress/`), figures with their provenance and captions, critique blockers with agree / disagree / comment, gate decisions, decision tests, and "your decision needed" cards. A stepper over `stage_machine.STATES` shows done, current, waiting, failed and skipped states, the round and the fix-loop count, and filters the stream by stage. Answers change a run only through the existing commands: `agents/stage_machine.py sign --by owner`, `scripts/scope_signoff.py sign --answers` (read back by `load_answers`), or `cloud/run_cluster.py <config> sign` for a mirrored run; each needs an explicit confirm and the owner's note. Chat goes to `claude-opus-5-5` through the official SDK (`anthropic==2.3.0`, new pin, imported on the first message): streamed, adaptive thinking, effort set explicitly, server-side refusal fallback, the rules and the run context as two cached system blocks, `[[file#anchor]]` citations that open the side panel, uncited numbers marked, a per-message cost from `usage` and a session cap (default $2) checked before each call. Guidance and corrections go to `<run_dir>/owner/feedback.jsonl` (anchor, kind, layer, optional proposed change) before Claude acknowledges them; the turn is kept in `owner/chat.jsonl`. A learning view lists feedback across runs by layer and exports a digest. The sidebar lists runs under `--roots`; "Build on this run" writes a draft under `<root>/_drafts/` (spec, derivations, engine choice, and each stored batch's reuse verdict from `compute.code_fingerprint`) and shows the commands, launching nothing. The compute panel runs `run_cluster.py <config> status|health|report-cost` read-only, at most once a minute and only while "live" is on. Self-tests RC1-RC11 were written first (α) on a synthetic run dir. (γ) Without --port a busy default port falls through to the next free one (an explicit busy --port is a one-line error), and a placeholder ANTHROPIC_API_KEY counts as missing (RC12, RC13).
