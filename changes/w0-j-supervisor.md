## Changelog

**W0-J (small version): between-run supervision off the laptop (`cloud/supervisor.py`).** Laptop sleep twice stalled all work between runs for about 8 hours. A loop now runs as a `cloud/vm_job.py` job on a small Coiled VM (2-vCPU worker, 2-vCPU scheduler; default name `ev-supervisor-gcc`, in the `ev` budget scope) with all its state in blob storage under `outputs/supervisor/<name>/`, so the laptop is only a client. Each loop it reads write-once request blobs from the laptop (`enqueue-merge`, `enqueue-collect <config.py>`, `enqueue-noop`); takes one merge-train step (ops/merge_train.sh's steps through the GitHub REST API: update the branch when it is behind its base, wait for CI, merge at the head sha only once every check run on every page, every commit status and the `.github/workflows/ci.yml` run on that head have succeeded; a failure, conflict, closed or missing PR, or 3 h of waiting skips it); collects every enqueued launch's labels from storage with `run_cluster.collect_from_storage` (storage only: no cluster is attached or stopped; a relaunch replaces the earlier copy), archives each to `collected/<launch>/<label>.tar.gz` and runs `scripts/harness_metrics.py` over every collected run (`metrics.json`, retried until stored); and writes `status.json` (heartbeat, merge queue, collection, paused runs, errors). A failing part is recorded and the loop goes on; a bad request is refused once. On the laptop, `status` reads status.json and exits 3 when it is stale or absent, `pull` fetches each collected run once into `~/modeling-agentic-keep/supervisor/` after checking its sha256, and `stop` stops this name's live cluster by id. Merges stay held until the owner provides a GitHub token: `start` passes `$GH_TOKEN` from the login keychain (service `modeling-agentic-supervisor-github`) with the new `vm_job --secret-env GH_TOKEN` (allow-listed, the job's environment only, refused before any cluster is created when unset). `vm_job start` now waits until its job has claimed its id: in the first smoke the client closed before the 5 MB task reached the scheduler and the job stayed `queued`. Resuming paused v2 runs is not automated: status lists them. Self-tests SV1-SV24 (supervisor), VS1-VS5 (vm_job).
