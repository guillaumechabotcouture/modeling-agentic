## Changelog

**The joint calibration reuses stored unit runs by job_sha, engine identity and adapter digest.** F6 run 1 (2026-11-16) stopped in calibration after 3,088 unit runs, which cost about $114. `compute.py` keeps a stored row only under the same whole-repo code fingerprint, so any harness edit, such as the calibration acceptance rule the owner is now deciding, would recompute every one of them. `toolkit/analysis/joint_calibration.py` now builds a pool of stored rows once per simulator (`stored_rows`), from **trusted files only** (`_trusted_sources`): a `points.jsonl` or `results.jsonl` whose `compute.py` summary `out_sha256` equals the file's digest, or a merged results file whose own `.reuse.json` digest does. A file altered after it was recorded is never a source (Codex P1). `Simulator._units` admits a stored row for a job (`_admit`) only when three things match. First, `batch.verify_rows` passes: the row's `job_sha` equals the job's, covering every input (engine reference and config, horizon, windows, unit, package, params, seed), and its engine identity (code, parameters, configuration) equals the current engine's. Second, the **adapter digest** matches: `adapter_digest`, over `toolkit/analysis/batch.py` and `toolkit/engines/horizon.py` (the code between job and engine call), equals the current one. It is recorded in each call directory's `adapter.json`; rows stored before this change are admitted only when `$MA_JC_LEGACY_ADAPTER_SHA256` attests the current digest. Third, every candidate per `job_sha` is tried, so an old engine's row never masks a current one (P3). Only the jobs left over go to the engine. **No stored file is rewritten** (P2-2/P2-3): a call whose `call<N>` directory already holds files, from an earlier launch or a continuation whose call numbers restart, writes to the first free `call<N+100000·m>`. Its results file is republished there in job order, with a digest sidecar, so it stays a valid `--prior` source and a trusted source for the next launch. The report records `adapter.stored_rows_reused` and `stored_rows_reused_legacy`. The CLI gains `--reuse-check`, a read-only count by call directory of the trusted files, stored rows, admitted rows, adapter and recorded runtime. Runtime (Python and package versions) is reported, not gated, as `compute.py`'s own reuse-check does. Self-tests JA26a-m. α's JA26a, b, e and β's JA26b, d, f, g, h failed first (β reproduces Codex's findings on 0f20399). Retro-check on F6 run 1's stored rows: the adapter digest at the F6 launch commit fb5f4c4 equals this branch's (48226c2b…). With it attested, `--reuse-check` finds 3,088 stored and 3,088 admitted (call1 1,236, call2 1,236, call3 309, call1001 307), each from its `points.jsonl`, whose summary digest matches.
