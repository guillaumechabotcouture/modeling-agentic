## Changelog

**v2 autonomy 1A: the PRESENTATION budget stop, the gate before a rewrite, fix-task checks, done_when rows, RETHINK back-edges and claim references.** Items are those of `docs/design/v2-autonomy-brief.md` PR 1A that the re-audit against `d4e2a67f` found open. Budget: the presentation review of the draft is part of the write-up, so `h_PRESENTATION` lets it use the write-up reserve as WRITE does (an accepted run whose WRITE spent into the reserve ended `budget_exhausted` at PRESENTATION with most of the reserve unspent); a write-up task's crash read-back allowance is computed from the same amount. With the whole cap spent the run still ends `budget_exhausted`. Gate: at a pre-write gate `v2_gate` reads `critique_presentation.yaml` as of the round the file states when that is an earlier round (`_earlier_round`); such a gate follows a post-write modelling fix, one round on, the draft is rewritten and reviewed again before the next post-write gate, and the earlier round's review failed the round check there (a schema repair and a paid review of a draft about to be replaced). The review's findings stay open and listed; the post-write gate still needs the current round's review. `open_findings` defers `category: PRESENTATION` findings before a draft, by the gate's own rule (`open_problems.after_write_item`). Fix-task checks: `done_when_regressed` and `done_when_unmet` rows carry `key` (their finding's id) and the frozen test, so each is its own ledger row and stall key, and `check_task` runs the test; `done_when_dropped` stays HIGH. The ledger keeps a test written as one mapping, keeps the gate's frozen test over a critic's later edit (`frozen_tests`), and takes the test a gate row carries. `check_task` leaves a gate-only finding (`fix_loop.GATE_ONLY`: the `done_when_*` and `critique_*` kinds) to the next gate instead of passing it by its absence from the harness checks; `Machine.harness_ids` adds the backend's spec and registry checks when a backend has them. RETHINK: `Machine._rethink` records why the run goes back (the gate's rationale, the round's rethink briefs, the open findings named or owned, with remedies); an unsigned spec is redrafted with them as feedback and a fresh count of tries (a signed spec still pauses for the owner's amendment); the engine pick receives the engine left and the reasons (`pick_engine(..., rethink=)`, recorded as `rethink` in `engine_choice.json`); the fix loop stops at the first rethink task (`skipped_rethink` in its summary). Claims: `render_claims.load_claims_tolerant` returns the valid claims and names each invalid one (`load_claims` is unchanged and still refuses the whole ledger); the v2 report renders the valid claims and reports each invalid one as a HIGH, non-declarable `report_claim_invalid`; `[CLAIM: id ]` is read as the renderer reads it. A fix task owns the fix files whatever stage its plan names (dead branch removed). Narrow Codex review, round 1 (γ): PRESENTATION's budget check is `_task`'s alone, so a completed review is replayed on resume with the cap spent; a write-up task's journal entry records its read-back allowance and an interrupted one is charged it (`_interrupted_charge`); `open_findings` uses the gate's two-file test for a draft; a withdrawn test is no test in the ledger; `load_claims_tolerant` isolates any per-claim failure; a bare claim id beside a reference is still reported and an invalid claim's reference is reported once; a back-edge from the gate reads the critics' description of the mismatch and no fix plan, and a fix plan that is not one adds no reason. Not in this PR: the reserve size (budget policy), judgement-only tests in the fix-loop trigger, strict test validation of carried blockers, a `claim_units` check in the v2 report, and the short-circuit when the only eligible engine was rejected.
