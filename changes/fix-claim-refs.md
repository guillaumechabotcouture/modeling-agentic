## Changelog

**Claim references repaired inside WRITE, never at the round cap.** Harness baseline hb2: 3 of 8 runs ended RUN_FAILED (gate rule 5, post-write) on non-declarable claim-reference findings first seen at the post-write gate of the last round, so nothing could repair them. Three causes, each now prevented by the harness. (1) `render_report` appended finding text (claims and required remedies) holding critics' `[CLAIM:x]` and the placeholder `[CLAIM:id]` to report.md unrendered, and `report_claim_unrendered` read them as the writer's: `render_claims.quote_refs` now renders a ledger reference in the harness's own blocks as its value and turns any other into the words `claim x`. (2) The writer repeated a declared remedy's placeholder in full: `write_declared` and the write-up findings WRITE passes to the writer keep ledger references and turn the others into words. (3) The writer named ledger ids in inline code: `render_claims.normalise_refs` reads an inline span whose whole content is a known reference or a known dotted/underscored id as that reference, in both the renderer and `report_claim_findings`. Anything left (an id outside the ledger, a bare id in prose, a reference in a fenced block) goes back to the writer inside WRITE (`Machine._repair_claim_refs`, at most `MAX_CLAIM_REPAIRS` = 2 sessions, history entries `claim_repair`), which costs no round. The gate still refuses whatever remains (non-declarable HIGH). A repair may only turn references into references, or it is undone (`undone` in its history entry) and the finding stays for the gate. It is undone when the draft is missing, unreadable or empty, when it lost more than a fifth of its words outside references, or when it added any digit string outside a reference (counted per occurrence, years included). Repairs are paid outside the write-up reserve, so the presentation review and the gate keep theirs. The draft before each session is kept in run_state.json until its check has run. A session interrupted before its check is undone when WRITE resumes, before the draft is read, and counts as one of the two. report.md is re-rendered after every repair session. A reference to an invalid ledger entry is reported once, as `report_claim_invalid`, and is not sent to the writer. Quoting puts rendered values back last, so a value is never substituted again, and it never rewrites a bare identifier the harness recorded. Code blocks are never normalised: fences after indentation, block-quote or list markers, closed only by a fence at least as long, and indented lines. Double-backtick spans are normalised. Self-tests CR1-CR22; T40b, T44b and T54 moved off the inline-code shape.
