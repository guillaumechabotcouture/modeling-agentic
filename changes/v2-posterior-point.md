## Changelog

**A declared net-effect posterior's verified chosen point is the point value of its columns.** Before, each uncertainty draw took whole posterior rows, but the point estimate of a posterior column still came from `fitted.yaml` (fitted kinds) or the card default, and the joint calibration held non-shared parameters at that same point. The headline plan and the calibration could therefore sit at a point the declared fit rejects. Now `uncertainty.net_effect_sample` also reads the fit's verified chosen point (`joint_region.verified.chosen.point`, in the signed bytes that `load_posterior` replays through `finalize()`). `uncertainty.posterior_point` sets every posterior column to it, in `core.Analysis.theta0` and in `joint_calibration.theta0` alike, as `set_joint` already moves shared parameters to the joint calibration's best point. A spec `engine_parameters` value for a posterior column that differs from the chosen point by more than 1e-6 x max(1, |value|) (the fit file's 6-decimal rounding) is refused with a message naming both values. An equal value is accepted, so an entry that only makes a column drawn can stay. A posterior file without a chosen point, or with a column missing or non-finite, is refused, with no fallback to card or fitted values. The sign-off precondition reads the same point, through `joint_calibration.theta0`, and so does the pre-run evidence the sign-off checks read (`decision_tests.prerun_evidence`). The joint calibration's benchmark targets calibrate their settings with a fitted posterior column at the chosen point, not at `fitted.yaml`'s value. Not covered: the `likelihood` and `posterior` calibration methods (`calibration.py`, `observed_targets.py`) build their engine parameters from the calibrated parameters and the spec values only, so other parameters stay at engine defaults, as before this change. The analysis manifest's engine record holds `point_source` (`{column: posterior_chosen_point}`) and `posterior_point`. Specs without the field are unchanged. The self-test fixture `net_effect_fit._fixture_placeholder` now writes a chosen point (default: the first row). These tests were written first and failed before the change: RNP3 and RPP2-RPP6 (with RPP4b, the equal-within-rounding case) in run.py, and PC18 in preconditions. RPP1 (no posterior: point values unchanged) passed before and after. PC17 now places the fixture's chosen point outside the hull (α-β).
