## Changelog

**Launchers pin priced VM types before any cluster is created.** On 2026-11-13 a `vm_job --cpu 8` request with the default `--memory` got Standard_F8s_v2, which cloud/vm_prices.yaml did not list; budget.py refused it only once the cluster existed, the cap stopped it, and every later f6 launch was refused until #230 priced it. cloud/vm_prices.yaml now states `memory_gib` per type. `budget.vm_types_for(cpu, memory)` resolves a request to the priced types with that many vCPUs and at least that memory (a type seen on our clusters first, then one of a series seen there, then least memory and cheapest), `budget.require_priced` refuses any unpriced type, and `budget.scheduler_vm_types()` pins 2-vCPU, 8 GiB schedulers. `vm_job up` and `run` pass Coiled `worker_vm_types` and `scheduler_vm_types` from the table, never cpu/memory, and refuse a request no priced type matches before any listing, budget reservation or cluster; `vm_job start` on a cluster made elsewhere refuses one whose live processes run an unpriced type or list an unpriced candidate type (`spec.prioritized_instance_types`: cluster 2376181 listed 16 worker and 50 scheduler candidates, most unpriced), or whose types cannot be read, then attaches to the cluster id it checked. `worker_side.attach_existing` pins one priced type (`ATTACH_VM_TYPES`), so a cluster an attach creates by accident (and shuts down) is priced too. Memory requests are read as Coiled reads them (GB is 10^9 bytes, GiB 2^30). `run_cluster` launch and `keeper` call `vm_request(cfg, compute)` before the budget guard: the run cluster, overflow pool and keeper constructors are pinned the same way, and an unpriced `compute.WORKER_VM_TYPES` or `overflow_vm_types` is refused before any reservation, key or cluster. Self-tests BR23a-g, VT1-5 (VT4c-e from Codex), OC1, BU7-7d, RC60a/d/e. Fail soft (owner, 2026-11-13; ε–ζ): an unpriced VM type never refuses a launch, blocks the scope or stops a running cluster. budget.py counts it at `fallback_bound` (the table's highest per-vCPU rate x margin x the vCPUs its Azure name states, or the largest type's bound), and `status` and the launch's budget line print a WARNING naming it (BR18 still flags it for the table). A request no priced type matches exactly gets the closest priced types that satisfy it, with a WARNING; only a request nothing in the table satisfies is refused. `vm_job start` and `run_cluster` warn instead of refusing (`budget.unpriced` replaces `require_priced`). Self-tests BR21b, BR23d, BR25a-c, VT3, VT4-4e, BU7, BU7b, BU7d.
