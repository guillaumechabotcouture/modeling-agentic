## Changelog

**The net-effect fit checkpoints every finished engine task, and a relaunch resumes from it.** The fit kept its results cache in memory only, so a stop at the cost cap would have lost every finished task. Under `vm_job.py` (`JOB_OUT` set, not a smoke), `net_effect_fit.py run` now appends each finished engine task to `$JOB_OUT/netfit_cache.jsonl` as it lands, through `lib.safe_io` (no link followed) with a flush and fsync per row. Each row holds a key, the engine `code_sha256`, the task's full job tuples and the result with its sha256. The key covers the engine code and every job's full parameter tuple, which includes the fitted values and the calibrated unit attribute, so it covers the existing cache key and its calibration. `run --resume-from <dir>` loads `<dir>/netfit_cache.jsonl` (`load_cache`) and runs only the missing tasks. It refuses, failing closed, when there is no cache file, a row is malformed, a row comes from other engine code, a key is not its task's, or a result does not match its sha256. A last row cut before its newline by the stop is dropped. Tasks are grouped and ordered exactly as in `benchmark.Runner._map`, and every result passes through its JSON form, so a resumed run returns what an uninterrupted run returns, with or without a checkpoint. No engine code changed, so the fingerprint is unchanged. Self-tests F16-F17 were written first and failed before the change. F16 uses a toy engine: it stops after 5 of 12 tasks, resumes, reruns only 7 and compares the results. F17 covers the refusals. No cloud run.
