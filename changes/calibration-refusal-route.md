## Changelog

**A calibration refused under a signed spec gets a planned spec patch before the pause (hb3 triage fix 2b).** In hb3, flu R1's refusal went to SPEC, but under `--signoff lead` the request carried no patch, so the lead amendment was refused and the run paused. The #339 redraft branch runs only for unsigned specs (`--signoff none`, the one mode in which SIGN does not sign). It is kept for them, and its history line now reads "redraft n of 2". Under a signed spec, `h_ANALYZE` marks the run as a signed amendment (`tries.spec_amendment`) and asks the fix planner for one SPEC rethink on the `calibration_refused` finding. The planner gets one retry when the plan does not validate, and below the task floor it is skipped. The call is journaled under a key bound to the refusal and the signed spec. `calibration_plan_problems` checks the plan: well-typed JSON, the planner's own checks, and amend.py's patch format. Applied in memory to the signed spec, the patch must change something, and only the calibration's `method`, `priors`, `parameters`, `range` or `scale`. The comparison is type- and key-sensitive. Parameters may only be reduced, priors only edited or removed, and a prior edit must change more than its source. The planner's record is `calibration_patch_r<round>.json`. The route, with the accepted patch itself, goes into `run_state.json` `tries.calibration_patch`, saved with the ANALYZE→SPEC transition. `rethink_request` uses it only when that transition brought the run to SPEC (`Machine._calibration_route`). The request is then the route's alone: a rejected plan gives a patchless request, never a same-round fix plan's patch. A cached request is replayed only for the same route (`calibration_key`). Under `--signoff lead` the route's patch is the request's `patch`, and `_lead_amend_locked` makes the provisional child. `toolkit/spec/amend.py` defers the child's imported open review conditions to the owner (`review_conditions.lead_defer`, D2, which gains `skip`), except parent findings the request does not name and findings the owner declined. Those stay open, so the child does not dry-sign and the owner decides. Under owner sign-off the request carries `proposed_patch`. `amend --from-request --proposed` applies that copy exactly as reviewed (it refuses beside `--patch`), and `next` says when `--finish` is needed. A fix-loop plan's SPEC patch is proposed to the owner the same way. With no valid patch the run pauses as before. A child never copies `calibration_patch_r<N>.json` (matched exactly), and that name is added to `harness_owned()`. Self-tests CRF5-CRF13.
