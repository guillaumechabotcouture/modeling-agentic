## Changelog

**The fix planner is told what a fix task may edit, and a fix that needs harness code is declared a harness gap.** In harness baseline hb1 every fix task planned a change outside what a fix task may edit (analysis outputs, the claims files, `data/README.md`, or harness code under `toolkit/analysis/`), and none of them changed a file. `agents/fix_loop.py` now holds the edit scope (`FIX_EDITABLE`: `analysis_settings.yaml` and `models/ext/`). The fix task's write scope (`agents/v2_sdk_tasks.py` `OWNS["fix"]`) is that same tuple. Each fix worker may write only the in-scope files its validated task names (`task_scope`). A folder keeps its trailing `/`. Its prompt lists them. The write hook now matches owned paths case-sensitively. The planner's packet carries `edit_scope`: the files, and the settings leaves of the backend the machine runs, which `h_FIX_LOOP` now passes in. Plan validation refuses a fix or decision_test task that names no files, and it refuses a file outside the scope. An absolute path, a `..` part, a backslash or surrounding space counts as outside. A finding whose fix needs anything else goes in the plan's new `harness_gaps` list with its `reason` and what it `needs`. That entry covers a blocking finding. The loop records it in `fix_plan_r<N>.json`, in its summary (`harness_gaps`, `harness_gaps_blocking`) and as a `harness_gap` event on the finding, which stays open. It is never a fix row. The next packet shows the reason. `agents/stage_machine.py` no longer takes the write-up-only route to WRITE while a blocking harness gap is open. `budget_ledger.json` and the task input and output files no longer count as changes the task made. The harness default plan names the whole scope. Retry and credit for fix tasks are unchanged. Self-tests F19-F22b, S_FIX_TASK_FILES, S_OWNS_CASE and HG1-HG1c failed before the fix. F19-F20c are built from the hb1 dengue, measles and tb R2 plans and impact rows.
