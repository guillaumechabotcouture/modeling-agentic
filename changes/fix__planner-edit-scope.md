## Changelog

**The fix planner is told what a fix task may edit, and a fix that needs harness code is declared a harness gap.** In harness baseline hb1 every fix task planned a change outside what a fix task may edit (analysis outputs, the claims files, `data/README.md`, or harness code under `toolkit/analysis/`), and none of them changed a file. `agents/fix_loop.py` now holds the edit scope (`FIX_EDITABLE`: `analysis_settings.yaml` and `models/ext/`). The fix task's write scope (`agents/v2_sdk_tasks.py` `OWNS["fix"]`) is that same tuple. Each fix worker may write only the in-scope files its validated task names (`task_scope`), and its prompt lists them. The planner's packet carries `edit_scope` (the files, and the settings leaves the analysis backend accepts) and `no_op_findings`. A no-op is a failed fix row from an earlier round that changed no file the task may edit. An hb1 row, written before `no_op` existed, is read from its `files_changed`. A failed task call (`task_failed`, still retried once), a decision test and a row whose check held are not no-ops. Plan validation now refuses three things: a fix or decision_test task that names no files, a file outside the scope (an absolute path or a `..` part counts as outside), and a fix for a finding whose earlier fix task changed no file. A finding whose fix needs anything else goes in the plan's new `harness_gaps` list with its `reason` and what it `needs`. That entry covers a blocking finding. The loop records it in `fix_plan_r<N>.json`, in its summary (`run_state.json` history) and as a `harness_gap` event on the finding, which stays open. It is never a fix row. The next packet shows the reason. A fix task that changes no file is recorded `no_op` and is not sent back for a second try. If its check fails, the row is failed. If its check already holds, the row gets no credit. `budget_ledger.json` and the task input and output files no longer count as changes the task made. The harness default plan names the whole scope, and it declares a no-op finding a harness gap instead of fixing it again. In `agents/stage_machine.py`, a loop that declared a harness gap no longer takes the write-up-only route to WRITE. Self-tests F19-F22e, S_FIX_TASK_FILES and HG1 failed before the fix. F19-F21c are built from the hb1 dengue, measles and tb R2 plans and impact rows.
